# 段落骨架标准 · LESSON_TEMPLATE.md

> 去留：长期。
> 规定每个授课段落的结构与顺序。与 TEACHING_STYLE.md 搭档：
> 本文件管「骨架」（有哪几块、什么顺序），TEACHING_STYLE 管「手感」（语气、密度、比方）。
> 立于 Lec 2 前置整改，固化 Lec 0-1 实际在用的段落结构。

## 一、动手段落（跑命令 / 派角色或子代理干活 / 学生做决策）
按此顺序，块可按难度浓缩但不可乱序：
0. 老师锚点：3 行，写法同第二节第 1 块（规则 32）。编号用 0，后面各块不重排。
1. 段落定位：第几课第几段、整课进度、上一步做了什么、这步做什么（规则 14/37）。
2. 这段为什么这么做：一句话（规则 37）。
   学完这步你会做什么：写一个具体的能力，不要写"理解某某"。
   对的例子：学完后你会建一个 Claude Code 角色文件，并能验证它真的被识别。
   错的例子：理解角色机制。
3. 核心讲解：按难度浓缩或展开，含 Level 1 对应（规则 11）。简单步骤可缩，不可全省（规则 12）。
   Level 1 对应：这步在网页版时代你是怎么做的。那时的痛点是什么。现在升级后解决了哪个痛点。
   对应 KNOWLEDGE_BASE 哪条知识（规则 10）：列出这步真正用到的协议、强化、补丁、Claude Code 机制。只列真用到的，不凑数。
   讲解骨架（最小版，Lec 2 立，Lec 3 起精雕细琢）：
   3a. 原理：为什么要有这个东西（一句话比方 + 不做会怎样）。
   3b. 操作：怎么做、涉及什么知识点。
   3c. 复杂产物拆段讲：文件/产物拆成 N 段，逐段说"这段是什么、为什么在、谁读它、什么时候读"，讲透一段再下一段（规则 51）。禁止整块甩出。
   3d. 联动讲解：按 3 触发条件（用到 2+ 旧概念 / 产物被 2+ 后续课用 / 学生可能问为何不分开）出现（规则 16）。
4. （已废。原「模式归属」块按乙写，抄规则 42：prompt 外注明要不要切 Plan Mode、谁来切。丙里改已有文件不切 Plan Mode（46A），规则 42 已废，改文件怎么走见规则 28。编号留空不重排。）
5. 终端命令 + 预期看到什么。没有命令写「本段无」（规则 6）。
6. CC 的 prompt：前面标「建议模型 + 一句理由」（规则 41）；prompt 第一句让角色先读定义文件（防反模式 3）；参考文件给具体路径（防反模式 7）。没有 prompt 写「本段无」（规则 6）。
7. prompt 关键点：讲 1 到 3 条，配反例，讲不这样写会出什么问题（规则 7）。
8. 审查清单：逐条信号，可勾选（规则 5）。
9. 反馈模板：填空式，不让学生从零想（规则 25）。

## 二、讨论段落（学生质疑 / 架构讨论 / 纯讲解）
按此顺序：
1. 老师锚点：3 行（分工 / 红线 / 这步我最可能犯的错）（规则 32）。
   第一行：分工。我讲课、执行，学生决策，网页版审查（只算半独立）。
   第二行：红线。不经学生同意不改文件，权限配置不碰（规则 66）。不编 KNOWLEDGE_BASE 以外的课程知识（规则 31）。
   第三行：这一步我最可能犯什么错。
2. 认错或肯定：先表态，不含糊。
   先写标题：直接说学生对在哪，或者老师错在哪。不绕弯。
3. 拆根因：E1-E4 分类。没有错写「本段无」（规则 6）。
4. 入库：有新反模式或新规则，现场登进本节挂账（交付物清单「推到结课的事」），写一句话与出处；整节课结课时编号入库（规则 45、87，问 365 甲、问 686 A）。没有写「本段无」（规则 6）。
5. 给选择：A/B/C + 推荐 + 一句理由，绝不替学生拍板。
6. 学生回复模板：填空或选择式。

## 三、不立模板的（刻意留白）
- prompt 正文：内容每次都变，硬套模板害灵活性。其「规矩」已在第 6 块和 TEACHING_STYLE。
- 审查清单内容：每步审的东西不同，现写。其「形式」（逐条、可勾）由第 8 块规定即可。
原则：反复出现且结构稳定的才立模板；一次性、内容每次变的，立了是枷锁。
