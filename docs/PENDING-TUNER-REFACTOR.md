### 改动必须先经学生同意（硬要求，违反要重来）

一，任何一处改动，给命令之前必须先给新旧对照。格式固定：

    ### 改动 N · 文件名 · 哪一节
    原文（出处：文件名 X 节）：
    （原样贴出要改的那几行，一个字不改）
    改后：
    （改完的样子，完整贴出）
    为什么改：（说清毛病和不改会出什么事）
    影响谁：（哪些别的地方指着这里、会不会跟着要改）

二，一组里有几处改动就出几个对照块，不要合并。
三，全部对照出完，停下来问：「以上 N 处，同意哪几处？」学生逐处回。
四，全部点头之后才给命令。命令里的改动必须和点头的对照一字不差。没点头的一处都不许写进命令。
五，命令跑完给一条验证命令，让学生核实结果和对照一致。

绝对不许：跳过对照直接给命令、把没点头的改动夹带进命令、把几处打包成「一组，同意吗」让学生整体点头。

### 讲解要求（上上个窗口就死在这）

学生不是来验收 diff 的，要看懂每一处为什么改。每组在给对照之前，先用大白话讲清楚，满足五条：

一，先讲这一组要动的每一节是干什么的——在系统里什么角色、谁读它、什么时候读。打比方讲，不要直接上术语。
二，再讲这一节现在有什么毛病。毛病要给出处（哪个文件、哪一节、哪句话）。还要说清不修会出什么事——具体后果，不是「会混乱」这种空话。
三，然后讲改完之后会怎样。这一节变成什么样、和别的文件关系变没变、哪些地方会跟着受影响。
四，每一处改动单独讲，不要几处合成一段。中间留空行。
五，顺序固定：先讲解 → 再出对照 → 停下等点头 → 同意后才给命令。

手感：句子短，一句话一件事，用句号断开。先打比方再上术语。一个代号第一次出现要讲清是什么。少堆图标，少堆编号代号，一段话里别堆超过一个代号。留呼吸感，分块写。
