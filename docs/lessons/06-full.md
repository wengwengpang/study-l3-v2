# Lec 6 · CLAUDE.md 第三层（灵魂课）完整笔记

## 本课一句话
给全项目宪法封顶：建「决策边界」（语义层，什么时候喊主人）+「权限系统」（机械层，CC 的手能伸到哪）。两条垂直的轴。

## 一、决策边界 D1-D7（写进 CLAUDE.md 第三层 A · 语义层）
比方：一张「哪些门必须喊主人」的门禁清单。
判据（本课新加的尺）：每类决策不只看属于哪类，还量两把尺——能不能撤销？错了影响多大？可逆且影响小→CC 自行；不可逆或影响大→喊主人。

五道领域门：
- D1 范围取舍：功能做不做、进不进 MVP。
- D2 数据结构演进：建表/加删字段/改约束。可空加列可自行；drop 有数据的表必喊主人。含「不做所以不预留」这类合并判断要拆开：不做是事实，不预留是取舍，取舍归主人（反模式 33）。
- D3 权限与安全口径：谁能看/谁能改。安全边界，错了影响大。
- D4 技术选型与锁定：选框架/库/架构，可逆性低，砸墙贵。
- D5 不可逆操作：drop/迁移/删文件/上线。喊主人+双确认+回滚方案（协议 12）。

两条特殊：
- D6 需求来源验货：每条需求验出身——已验证/AI 假设/教学驱动，物理分开（反模式 19、32）。横切所有需求，不属单一领域。
- D7 元触发器：罩在 D1-D6 之上。CC 没把握、缺上下文、或技术结论里藏取舍→停下上报，禁止自己猜。口令：这里面有没有藏着一个该我拍的取舍？

## 二、权限系统 settings.json（机械层）
三档 = 三种门牌：allow 绿牌（CC 自刷卡）、ask 黄牌（按铃喊你）、deny 红牌（焊死）。
写法：Tool 或 Tool(specifier)，工具名首字母大写（Bash/Read/Edit/Write）。
撞门顺序：deny → ask → allow，撞上第一个就停。后果：红牌永远赢，再宽的绿牌也撬不开红牌。所以绿牌可大方，红牌是真安全网。
本项目配置：
- 红牌：偷密钥（.env/secrets）、rm -rf、sudo、curl/wget。
- 黄牌：git push、prisma migrate、写 prisma/、写 CLAUDE.md、写 .claude/。（补强 4：黄牌别塞满，否则按铃烦死，护栏形同虚设。）
- 绿牌：读文件、git 只读、跑测试/lint、列目录。

## 三、两轴垂直（本课最重要的认知）
settings.json 管「动作类型」（机械层，管手）；D1-D7 管「决策类型」（语义层，管脑）。
机器的牌子只贴得住「能变成命令/文件操作」的东西：D5(rm/drop)、D2(写 prisma/) 贴得住；D1 范围、D3 口径、D6 来源、D7 藏取舍是纯判断，没有对应命令，贴不了牌，只能靠 CC 读宪法自觉。
结论：危险的手用铁墙焊死，危险的判断靠宪法约束。两层互补，缺一不可。

## 四、行业校准（四条补强的来源）
- 人在环内(HITL，事前批) vs 人在环上(HOTL，事后拦)：高风险不可逆→HITL；中风险可逆→HOTL。
- 三种审批模式：事前批 / 事后审 / 置信度触发。D7 本质就是「置信度触发」，不是一类领域（补强 2 依据）。
- 审批阈值普遍绑「可逆性 + 影响」，不绑功能类别（补强 1 依据）。
- 审批疲劳：什么都塞进 ask，复审的人被淹没、代理动不动卡住，护栏就垮（补强 4 依据）。
- 安全：配置文件是攻击面，有 CVE / PyPI 蠕虫经由 hook 在同意前跑代码（规则 66 + BACKLOG 9 依据）。

## 五、新规则 / 反模式
- 规则 66：约束 CC 的配置文件由学生亲写（利益冲突 + 攻击面）。
- TEACHING_STYLE 第八：填空模板不替代讲解。
- 反模式：无新增（反模式 3 已罩住「JSON 写对≠CC 识别」）。

## 六、验证（现场复演反模式 3）
学生一度写「JSON 格式对，实际跑必定是识别」——正是反模式 3（表象成功≠实质生效）。改跑 /permissions，机器确认三档真加载，才算数。呼应信仰二：验证先于信任。
