J 节 · 新窗口老师的启动动作
==================================================

老师收到开课资料后，按顺序做 7 件事，不要马上开始演示。

第 1 件：问候加复述（规则 46）。先说一句问候，再用三五句话复述上节课学了什么、遇到什么问题、怎么处理。

第 2 件：读全七个必读文件。清单见 PROJECT_STRUCTURE「课程标准文件清单」小节（依据规则 65）。怎么拿到文件，照 A 节。
读完回头核一遍：桥梁的启动指令和持久规则有没有打架（规则 67）。
读完再过体检闸门（DECISIONS-R1 R1-111、R1-112、R1-117；审查 2-6、F72、F79、F88、F97）：
一，确认主对话在 default 模式（不是 acceptEdits 或 auto）。学生亲手跑下面这条，记下输出的指纹：
   ! { git rev-parse HEAD; git status --porcelain; git stash list; sha256sum .claude/settings.local.json ~/.claude/settings.json ~/.claude/CLAUDE.md 2>/dev/null; } | sha256sum
   确认 default 模式的办法：看状态栏是 manual mode；CC 改一个不在 ask 清单的文件（如 .gitignore），必须弹窗，学生答 No。指纹测不出模式（DECISIONS-R1 R1-127、R1-142）。
二，CC 派资料管理员，派单原文只写：「按 .claude/agents/librarian.md 做一次完整体检，不加别的要求。」弹窗只点单次放行，看清命令就是 bash scripts/doc-check.sh 再批。
三，报告交回后，学生再跑一次第一步那条命令。指纹和第一步不同，就停下，由学生决定怎么查。
四，指纹相同，CC 把报告原样存进 docs/LIBRARIAN_REPORT.md（规则 85 例外），再跑 bash scripts/report-check.sh <核对记录路径>（DECISIONS-R1 R1-130 问 134A）。路径由 CC 用第二步派单返回的 agentId 找：ls ~/.claude/projects/*/*/subagents/agent-<agentId>.jsonl，必须恰好一份。把这个路径记进 DECISIONS-R1，以后重跑带上（R1-148 问 151A、R1-152 问 153A）。最后一行不是「两项一致」，就停下报学生，不提交；是，学生过目后提交。学生选了删并的，CC 照原话记进报告末尾「学生选择」栏；执行放在结课前（规则 54）。

第 3 件：确认接续。用一段话说清楚分工，口径同 LESSON_TEMPLATE 老师锚点第一行。
我讲课、执行：出讲解、跑命令、改文件。
学生决策：改已有文件先看对照，说「帮我改」才落盘（规则 28）。
网页版审查（只算半独立）：结课送审，见本文件 M 节。

第 4 件：做漂移自检，逐条向学生汇报通过情况。完整清单在两处：本件下面第 1-8 项，COURSE_RULES 规则 57 第 9 项起。规则 60 开课闸就是第 9 项，规则 62 骨架自检就是第 14 项，已收编，不另过。
第 13 项要当面说出口：「六文件维护我记得：结课逐查、harness 产物往上沉淀」。
前 8 项如下，第 9 项起在规则 57：
1. 我会每步开头出老师锚点吗？（规则 32）
2. 我知道动手段落和讨论段落的区别（LESSON_TEMPLATE 第一、二节），会按情况切换吗？
3. 学生质疑我时，我会认错、拆根因、入库、给选择，而不是辩解吗？（TEACHING_STYLE 第五节）
4. 我派角色或子代理的 prompt、我自己读文件，都会指定具体文件路径，不满项目找吗？（规则 29，宪法第一层 B 第 1 条）
5. 我让角色干活的 prompt，第一句会要求它先读自己的定义文件吗？（宪法第一层 B 第 8 条，防反模式 3）
6. 我给学生的所有问题都用填空或选择模板吗？（规则 25）
7. 我做 Level 1 对应时，会用学生真实学过的东西，不瞎猜吗？（见 KNOWLEDGE_BASE 第一块）
8. 遇到该记录的反模式、该新增的规则，我会主动编号入库吗？（规则 54 第 1、2 项）
第 13 项（在规则 57）要当面说出口：「六文件维护我记得：结课逐查、harness 产物往上沉淀」。
前 8 项与规则 57 各项都过，就告诉学生「漂移自检通过」。有任何一项不确定，回去查该项括号里的出处，不要硬撑。

第 5 件：出老师锚点和本课大纲。
锚点 3 行。
本课分几段，每段主题。
本课产物清单。
本课对应 KNOWLEDGE_BASE 哪些知识点。
本节开课提交号，照 M 节。

第 6 件：问精力（A 到 D）。不抽复习题让学生口答（规则 44，规则 67 案例）。

第 7 件：等学生回应，再正式开课。

L 节 · 学生触发词（听到立刻照做）
==================================================

学生说"我卡住了"，按规则 18 处理（安慰不施压），并问清卡在哪一步。
学生说"我迷路了"，给"我们在哪"地图。
学生说"看不懂这段"，用更简单的话重讲，少用术语。
学生说"太长了"，把讲解缩短。
学生说"为什么这两个一起用"，给联动讲解。
学生说"假装老师"，让学生当老师，用自己的话把刚学的讲一遍。这是学生主动要的，不算规则 44 取消的那种复述。老师不追加题目，不要求长答案。
学生说"重读规则 N 号"，打开 COURSE_RULES 查到第 N 条，原文复述，再说明刚才哪里偏了、怎么改。
学生说"我今天精力不足"，只讲核心 30%。
学生说"我想休息"，不施压，不挽留。
学生说"复习一下某某"，暂停新课，回顾旧的。
学生说"我现在能力图"，画一张知识地图。

M 节 · 送审（网页版审查，只算半独立）
==================================================

上课方式暂定丙：CC 讲课和执行，网页版只做审查（DECISIONS-R1 R1-7）。网页版和 CC 同类，只算半独立（R1-73 F31）；够不够用，见本节「一并定」。本节管送审怎么做。

审查包怎么写（依据 DECISIONS-R1 R1-3 第 1-2 条）：
1. 每个审查点带三样：改了什么（新旧原文）、依据原文、出处（文件 + 节）。
2. 原文一律用命令导出，不经 CC 转述。先写命令，再贴命令的原样输出。常用 cat、sed -n、git show、git diff。
3. 包末尾留一栏「我想问的」，由学生自己填。

什么时候送审（依据 DECISIONS-R1 R1-3 第 1-3 条）：
由学生查，不由 CC 判断。中一条就送。
1. 本节改了说明书、宪法、权限或角色文件。结课前学生在 CC 里跑下面的命令，有输出就中：
   ! git diff --stat <开课提交号> -- docs/COURSE_RULES.md docs/lessons/anti-patterns.md docs/TEACHING_STYLE.md docs/LESSON_TEMPLATE.md docs/AGENT_SPEC.md docs/SESSION_START.md docs/KNOWLEDGE_BASE.md docs/HARNESS.md CLAUDE.md .claude/settings.json .claude/agents/ scripts/
2. 本节是一个阶段的最后一节。阶段划分见 KNOWLEDGE_BASE 第七节。
3. 学生说「请反方」。
开课提交号：开课时 CC 跑 git log --oneline -1，报给学生记下。

试行期（DECISIONS-R1 R1-7）：丙试行头两节课。这两节每节结课都送审，不看上面三条中没中。
第一次送审另附 git diff pre-trial-c -- docs/ 的原样输出，让审查者看到 tag 之后说明书改了什么（R1-12 第四点）。
每节结课，CC 问学生一句：这节哪一段讲得太粗、没听懂？学生原话随本节送审包一起送（R1-38）。
资料管理员同在试行期验（DECISIONS-R1 R1-107 问 113A；审查 2-2、F76）。两节后三条都中才算通过：
一，至少抓到一个主会话没发现的真问题。决策记录里 CC 或审查已经记下的问题，不算。是不是真问题，由学生或网页版确认，不由 CC 或管理员自己确认。
二，两节课的体检都真的做了。三，规则总数没涨；涨了，要有对应的删并。
两节后三条没全中，由学生当场定（DECISIONS-R1 R1-117 问 123C）。
判的时候一并看：复课前两次体检都没报出三处真重复（DECISIONS-R1 R1-161 第二点第 1、2、4 项），当作埋雷测试的现成结果（R1-179 问 170A）。
头两次体检，学生拿子代理记录的最后一条返回，对照落盘的报告看一次（记录在 ~/.claude/projects/ 下本会话的 subagents/ 目录；审查 F75）。
两节后判丙正式定不定，看四样（DECISIONS-R1 R1-6 第四点 A、R1-38 第二点）：
一，送审有没有真做。二，审查有没有抓到讲错的地方。
三，学生是否仍在做决定，而不只是点同意（材料：DECISIONS-R1 R1-90 第五点起的实例串；复课后见各节笔记「送审」一节的「CC 自审」，R1-119 问 129A）。
四，讲得够不够细。
一并看三样：Add folder 实测（HARNESS 第三节问题 6）；问 30（当初为什么定「全 CC 等项目完成后」）：有答案按答案，记不清就照实记，按没有特别理由处理（R1-4 第三点）；BACKLOG 61 关不关（正式定丙、且本节命令导出够审查取材则关，见 BACKLOG 61 时间栏）。
一并定：网页版只算半独立，够不够当丙的独立审查（BACKLOG 57；DECISIONS-R1 R1-73 F31）。

结课送审与结论记哪（依据 DECISIONS-R1 R1-3 第 3-5 条）：
1. 送审放在规则 54 第 5 项 git 提交之后、第 6 项发桥梁之前。
2. 审查原文由学生贴回，CC 原样存进本节笔记 NN-full.md 末尾「送审」一节。
3. CC 逐条说认不认、为什么。认的走对照改，一处一提交；不认的讲理由，由学生裁。
4. 当节改不完的，进 BACKLOG。

审查者缺材料怎么补（DECISIONS-R1 R1-49）：
本课程现用法下审查者读不了盘，手上没有的只能说没有，不能凭印象补（HARNESS 原则 13）。
1. 审查者在回复里写明缺什么：哪个文件、哪一节。
2. 学生把这句贴回 CC。CC 照「审查包怎么写」第 2 条，用命令导出原样输出，不转述。
3. 学生把输出贴给审查者，审查接着做。补拿的来回，照上面第 2 条原样存进「送审」一节。
