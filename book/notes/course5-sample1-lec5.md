## 二、知识点清单

归类简写:【工程】= 数据库或软件工程本身的知识;【协作】= 怎么和 AI 协作干活的做法;【课务】= 纯属这门课怎么上的安排;【拿不准】照写。

### (一)开课(1-166 行)

1. **Lec 4 复盘**(14-20)【课务;ADR 的定义属工程】
   上一课做了:激活并验真 architect 角色;用「6 必问」做约束分析、「四象限」做技术选型、ADR 留痕(16-17)。四个分叉的拍板结果是:鉴权走 DB session、Redis 延后、实时延后到 Lec 13 上 WebSocket、校验用 Zod(18)。学生切开了「约束驱动」和「教学驱动」两类需求,催生反模式 32(19)。老师给 ADR 的括注是「架构决策记录,写清背景/决策/后果」(17)。

2. **分工和两条红线**(22-26,102-103)【课务】
   老师出 prompt、命令、诊断;学生在 Claude Code 里真实执行并拍板;CC 的输出贴回来老师诊断(24-25)。红线原话:「我不替你直接改文件,我不让 CC 自己编课程知识」(26)。

   原话:「这 7 个文件在你机器上,不在我上下文里。我没有,也不会凭印象编」(31)。对应反模式 1,全称「假设 AI 知道我没说的事」(31)。

   用 for 循环把 7 个文件依次 cat 出来,每个前面 echo 一行分隔(39-43);再跑 `git status` 和 `git log --oneline -3`(46-47)。预期:working tree clean,最近三条提交是 17bfce1 / 763360d / 934107d(50)。7 个文件名见 39 行。

6. **漂移自检的内容**(69-97)【课务;第 11 项属协作】
   K 节 8 项(72-79):每步出锚点;样板 A(动手)和样板 B(质疑讨论)会切换;被质疑时「认错→拆根因→入库→给选择,不辩解」;给 CC 的 prompt 指定具体文件路径;让 architect 干活第一句先读定义文件;给学生的问题都用填空/选择模板;Level 1 对应只用学生真学过的;新坑新规则主动编号入库(规则从 66 起,反模式从 33 起)。规则 57 追加三项(82-84),其中第 11 项是「跑完命令拿真实输出核对,不信『成功』二字」(84)。git 核对时再说一次「看真实输出不看嘴」(89)。

### (二)第 1 段:从 PRD 推实体(167-373 行)

12. **schema 是房子的户型图**(177,181-185)【工程】
    比方:PRD 是业主说「我要几间房、各干什么用」;UI 是「每间房长什么样」;schema 是「承重墙在哪、房间怎么连通、水电走哪」(183-185)。实体清单是户型图的第一笔:「先定『有几个房间』,再谈每间多大、怎么连通」(177)。

13. **为什么建模放在写代码之前**(187-188)【工程】
    「改户型图很便宜,改盖好的房子很贵。」建模放前面,是为了把贵的错挡在前面(188)。

14. **为什么把建模交给 architect 角色,不直接列表**(190-192)【协作】
    「列表谁都会列。但建模是权衡活:要不要拆表、要不要冗余、关系怎么连,每一步都有取舍。」(191)architect 带着 6 必问、四象限、ADR,每个决定能追到 PRD 哪一条,还留痕;重思考活所以用 opus(192)。

15. **名词法:从 PRD 推实体**(194-196)【工程】
    PRD 里反复出现的核心名词就是候选实体。例子:用户、项目、任务、成员关系、通知。「先把名词抓出来,不急着写字段。」(196)

16. **Level 1 对应(第 1 段)**(200-203)【课务;"每张表可追溯"属工程】

82. **onDelete 是什么**(775-778)【工程】
    两张表用外键连着像「父子」:project 是父,它底下的 task 是子。onDelete 规定的是「父被删的瞬间,子该怎么办?」(778)

83. **onDelete 的三种态度**(780-783)【工程】
    - Restrict(拦着):只要还有子,就不许删父。
    - Cascade(连坐):删父,子跟着一起没。
    - SetNull(断亲):删父,子还在,只是把外键置空。

84. **onDelete 为什么必须现在定**(785-786)【工程】
    它是写进 schema 的硬约束,Lec 9 建库就定死了,改它要迁移。属于「一锤子买卖」,和硬删除同一性质。

85. **MVP 没有删除故事时,onDelete 只是一道防护栏**(788-791)【工程】
    没有删用户、删项目、删任务的功能,onDelete 几乎不会被触发(789-790)。问题因此变成:「万一哪天真删了父,你希望默认是『被拦住』还是『悄悄连坐删一片』?」(791)

86. **三个选项各自的代价**(793-799)【工程】
    - 全 Restrict 最安全,代价是将来做「删项目」功能得先写「先删子再删父」的逻辑(795)。
    - 局部级联:删 user 清 session 合理;删 project 自动清 membership + task 危险,「一删项目几十个任务无声消失」(797)。
    - SetNull 分配人:删 user 时它负责的 task 不删,assignee_user_id 置空变回未认领,其余照样拦(799)。

87. **按数据的性质分三类定 onDelete**(801-816)【工程】
    - session 是「人的随身物品」,人没了跟着清掉,用 Cascade(804)。
    - task 是「公司的资产」,员工离职资产不能蒸发,留下变成无人认领等重新分配,用 SetNull(805)。
    - project 是「大楼」,不能因为想拆楼就把楼里所有东西无声铲平,用 Restrict(806)。
    - 选项:A 全 Restrict;B SetNull 分配人 + sessions 对 user 用 Cascade;C 局部级联(811-813)。推荐 B,理由是符合「数据资产不无声蒸发」的安全直觉,「比无脑全 Restrict 更贴业务,比局部级联安全得多」(816)。A、C 被否。

## 三、讲法特征

1. **开课先走一串固定动作,再讲课。** 顺序是:问候并复盘上一课(14-20)→ 分工和红线(22-26)→ 要 7 个文件(28-48)→ 漂移自检逐条报(69-97)→ 老师锚点(101-104)→ 大纲并让学生选范围(106-118)→ 复习 2 题(122-132)→ 问精力(136-140)。学生回了填空(150-152)才正式开讲。

2. **每一段用同一副骨架。** 段落定位(上一步 / 这一步 / 进度百分比)→「这段为什么这么做」→ 3a 原理 → 3b 操作 + Level 1 对应 + 对应知识点 → 模式归属 → 建议模型 → prompt → prompt 关键点 → 审查清单 → 反馈模板 → 窗口体感。三段分别在 169-271、376-499、618-747。标题里明写的只有 3a 和 3b(179,198,388,417,630,653);自检里说的 3c 拆段、3d 联动(87)没有单独标题,第 3 段有一小节叫「联动讲解」(664)。

3. **一个比方贯穿全课,每段往前推一格。** 户型图(182)→ 先定有几个房间(177)→ 家具和全屋装修标准(384-393)→ 接水电、正式施工图(626-627)→ 蓝图不是房子(650-651)。

4. **每个概念和每个决策都以「打个比方」开头。** 决策点的固定格式是:纠结什么 → 打个比方 → 给选择 → 我推荐 + 理由一句。见 292-309、311-325、327-345、773-816。

5. **复杂产物拆三步,每条 prompt 只做一步并写死停止条件。** 208-211 说明拆法;停止条件在 244、470、717、868。每步之后必有一轮审。

6. **prompt 后面必跟「关键点(配反例)」。** 每点都说「不这样写会怎样」,见 247-250、473-476、720-723。

7. **学生动手的方式是复制、执行、贴回,回答用填空。** prompt 和命令都标「直接复制」(221,439,685,851);学生的每次回答都是填空模板(142-145,351-355,580-586,825-828)。

8. **验收靠「逐条核」和「预期」。** 贴回后老师对着审查清单一项项核(276-284,504-513,896-909);每条命令先给预期(50,1056,1213,1245,1443,1540),再拿真实输出比。核出问题就直说没匹配上(1569)。

9. **碰到 AI 产出里藏着的取舍,老师停下来单独拎出,讲清后把选择权交回学生。** 硬删除(522,547)和 onDelete(769-771)都是这样处理。老师给推荐,但声明不代拍(563),有一处明说不给强推荐(549)。

10. **结课按清单走,一条命令一个独立代码块,每条配验证命令和预期,桥梁最后发。** 见 1122、1174、1671、1691。出错时先认(1591)、再看原文(1578)、再精确补(1597)。
