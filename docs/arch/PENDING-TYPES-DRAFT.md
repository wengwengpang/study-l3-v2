**N5 空查询校验归谁（C5）**
- 事实：本版没有接口收查询参数（契约:303）。
- 取舍：要不要为它设一个名字。
- A：shared 放一个空查询 schema，契约点名，成第 20 个名字。前端不用，过不了 ARCH:173。
- B：后端自有一处统一检查，不进 shared，不点名。有接口开始收查询参数时再逐个点名。
- C：后端每个接口各写一个空 schema。
- 推荐 B。只有后端用。逐项列参数名照旧（契约:771）。要回写契约:113。

**N6 ProblemType 字面值的形式（标1，标21 未核）**
- A：https 绝对 URL。要先有域名，项目还没定。
- B：不依赖域名的绝对 URI，与 instance 同一思路（契约:620）。
- C：短字符串，不是 URI。与 RFC 9457 不符（未核）。
- 推荐 B。不用写域名，about:blank 也是绝对 URI。

**N7 错误外壳哪几样必填（标1）**
- A：问题类型、标题、状态码、编号必填，说明可省。
- B：五样都必填。
- C：都可省（RFC 的口径凭记忆，未核）。
- 推荐 A。前端只靠 type（契约:261），标题和编号过滤器总能给（契约:246、253）。框架退回未必有合适的说明（推断）。

**N8 逐项问题的子形状（标21 未核）**
- A：每项写指向哪个字段加一句说明，不带 Zod 内部结构。
- B：Zod 的问题列表原样透出。
- C：只给一个键名数组。
- 推荐 A。B 让库升级牵动接口。C 说不清类型不符。

**N9 哪些 400 用 ValidationProblemDetails**
- 事实：契约:118 只明写多余字段，契约:249 写「带逐项问题」。
- A：管道拦下的都带逐项。JSON 坏了（契约:212）和 Service 的业务 400（契约:408、429、463）用 ProblemDetails。
- B：只有多余字段带。
- C：400 全带。
- 推荐 A。管道本来就有逐项信息。JSON 坏了没有字段可指。

**N10 登录请求的校验口径（C6，标10）**
- A：只校形状与上限，不套注册规则，不合规的凭据走 401，空值回 400。
- B：套注册规则，短密码回 400。
- C：不校内容，空值也走 401。
- 推荐 A。合乎统一提示（PRD:161）。D9 到 D20 改过一次规则，再改时老账号不能登不上。

**N11 密码上限（标10，标19 未核）**
- 事实：D20 只给下界，算法和上限在 BACKLOG 82（只凭 PRD:306 转述）。
- A：本节定一个值，建议 128（假设），定算法时复核。
- B：只写下限，上限随 BACKLOG 82，其间接口无上限。
- C：先写底线 64，以后放宽。
- 推荐 A。接口不宜无上限（超长输入耗哈希算力，未核）。
- 提醒：bcrypt 的 72 字节限制（未核）装不下 64 个中文。选它会碰「不截断」（契约:126），要转告 BACKLOG 82。

**N12 长度按什么单位算（标18 未核）**
- A：全部按 Unicode 码点，要多写一段自定义校验。
- B：全部按 JS 字符串长度（Zod 默认，未核），emoji 算 2。
- C：密码按码点，其余按默认。
- 推荐 C。下限是安全底线，8 个 emoji 不该算够 15 位。标题上限差一点没后果。

**N13 邮箱格式与长度（标11 语法一节未核）**
- A：轻校验，@ 两边非空，总长上限 254（未核）。
- B：用 Zod 内置邮箱格式（规则随版本，未核）。
- C：只判非空。
- 推荐 A。首版不发邮件（PRD:113），严格格式验不了真伪，只会误伤。选之前先核 OWASP 那一节。

**N14 截止日期取值范围（标7）**
- 事实：判过期的「今天」本版不定（PRD:356，BACKLOG 77）。
- A：只校合法日历日期，不限过去。
- B：不许过去的日期。要先定时区。
- C：另加年份范围。
- 推荐 A。PRD 没有这条规则，B 压在 BACKLOG 77 上。

**N15 空更新（标6）**
- A：两个接口的空对象都回 200，什么都不改。
- B：改任务回 200；改状态必须带状态，否则回 400。
- C：都回 400。
- 推荐 B。改任务与「改成原值不算变化」同口径（PRD:357）。改状态只有一件事可做，空请求多半是前端写错，不该藏住（契约:652 同一思路）。选 B 要给契约:675 加一句。

**N16 任务负责人在 Task 里怎么表达**
- 依据：要 id，前端拼成员状态区用（契约:715）；要邮箱，用于显示（ARCH:351；PRD:323）。
- A：一个子对象，含 id 和邮箱，未分配时整个为空。
- B：两个平铺项。
- C：只给 id，邮箱查成员列表。执行者调不了成员列表（契约:398），排除。
- 推荐 A。不会出现有 id 没邮箱。

**N17 未认领要不要单设一项**
- A：不单设，任务负责人为空就是未认领（PRD:62），ARCH:133 的「未认领判定」回写。
- B：后端算一个标记。
- 推荐 A。「可能卡住」要单设，是因为它靠服务端时钟、执行者不可见（契约:717）。未认领不是，执行者也看不到这类任务（PRD:297）。

**N18 响应只带页面要的，还是多带（标9）**

- B：Task 多带状态时间和分配时间。契约:719 已否决前端自算。
- C：全部资源带创建、更新时间，Task 带所属项目 id。
- 推荐 A。只加不改。

**N19 子形状要不要公开名字**

- B：公开并回写契约。

- A：不允许，只许去空白这种不改类型的，z.infer 一种类型就够。
- B：允许，前端另用输入类型（凭记忆，未核），要修订 ARCH:252。
