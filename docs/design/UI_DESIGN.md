# UI 设计 · study-l3-v2
> designer 角色基于 docs/design/PRD.md 十七条用户故事产出。
> 口径：以权限矩阵 + 审定决策记录 D1-D9 为准（Lec 3 确认）。
> 可追溯性用 US 编号标注（US 编号随 PRD 稳定，比行号可靠）。
> 本文件随 Lec 3 逐段填：页面结构 → 主流程 → 异常流程 → 三态 UI → 视觉规范。

## 一、页面结构

### D6 任务入口决策
采用「单页面 + 按角色条件渲染」。
理由：D6 只规定可见范围（负责人全部+自己，执行者仅自己），入口结构留给 designer。
单页面保持「任务统一入口」的产品心智，用权限控制数据范围与操作入口，避免维护两套重复页面。

### 页面清单（10 个）

1. 登录页
- 访问层级：公开，未登录可访问。
- 核心元素：邮箱输入、密码输入、登录按钮、注册链接、登录错误提示区。
- 服务故事：US-A02。
- 角色差异：无；登录后按项目内角色决定可见内容。

2. 注册页
- 访问层级：公开，未登录可访问。
- 核心元素：邮箱输入、密码输入、注册按钮、登录入口、邮箱已用提示、密码规则提示。
- 服务故事：US-A01。
- 角色差异：无；注册成功进入已登录状态。

3. 项目入口 / 跨项目总览页
- 访问层级：需登录，按角色区分。
- 核心元素：当前身份、登出入口、项目列表、进入项目入口、创建项目入口、负责人跨项目总览区。
- 负责人：可创建项目；负责多个项目时看各项目整体进度与成员分布；点击进入项目任务列表。
- 执行者：只看自己已加入的项目入口；不显示创建项目、不显示跨项目总览。
- 服务故事：US-P01、US-P02、US-05、US-R01、US-A03（登出入口在此）。

4. 创建项目页 / 面板
- 访问层级：需登录，仅负责人；执行者不显示入口。
- 核心元素：项目名称输入、提交按钮、取消返回、名称必填提示。
- 负责人：填名称并创建，创建者自动成为该项目唯一负责人。
- 执行者：不显示入口；强行访问提示权限不足。
- 服务故事：US-P01、US-R01。

5. 项目主页 / 负责人进度视图
- 访问层级：需登录，负责人主视图；执行者不显示此视图。
- 核心元素：项目名、任务总数、已完成、进行中、未开始、完成率、风险提示区、成员任务状态区、进入任务页入口、进入成员页入口。
- 负责人：全员任务状态同屏；项目整体完成比例可见；低完成率且临近截止时显示风险提示。
- 执行者：不显示此视图；进项目后默认落到任务页的「我的任务」范围。
- 服务故事：US-01、US-04、US-08、US-R01。

6. 任务页（统一入口，按角色条件渲染）
- 访问层级：需登录，按角色区分。
- 核心元素：任务列表、状态、负责人、截止日期、排序/筛选入口、详情入口、状态更新入口、负责人专属创建/分配入口。
- 负责人：全项目任务列表；可创建/分配/换负责人；看未认领标记、卡住标记；按截止日期排序筛选。
- 执行者：只显示分配给自己的任务；可更新自己任务状态；不显示创建、全团队列表、未认领/卡住管理入口。
- 服务故事：US-03、US-06、US-07、US-02a、US-08、US-R01。

7. 任务详情页
- 访问层级：需登录，按角色区分。
- 核心元素：标题、描述、状态、负责人、截止日期、状态更新入口、负责人专属分配/编辑入口。
- 负责人：可看项目内全部任务详情；可换负责人、设截止日期、更新状态。
- 执行者：只可看分配给自己的任务详情；只可更新自己任务状态；不可设截止日期、不可换负责人。
- 服务故事：US-03、US-06、US-07、US-08、US-R01。

8. 任务创建 / 编辑页或面板
- 访问层级：需登录，仅负责人。
- 核心元素：标题输入、描述输入、负责人选择、截止日期设置、提交按钮、取消入口。
- 负责人：创建任务；分配或换负责人；设截止日期；暂无其他成员时允许不分配，任务进未认领状态。
- 执行者：不显示入口；强行访问提示权限不足。
- 服务故事：US-03、US-06、US-02a、US-08、US-R01。

9. 项目成员页
- 访问层级：需登录，仅负责人。
- 核心元素：成员列表、姓名或邮箱、角色、邀请入口、角色选择、改角色入口、重复成员提示。
- 负责人：看所有成员及角色；邀请成员（必须指定角色）；改成员角色。
- 执行者：不显示入口；强行访问提示权限不足。
- 服务故事：US-R02、US-P02、US-P03、US-R01。

10. 站内通知区（P2 延后，非独立页面）
- 访问层级：登录后显示，负责人相关。
- 核心元素：未读预警入口、预警列表入口、卡住任务提示。
- 负责人：任务判定卡住后，通知区看到站内提醒。
- 执行者：当前 PRD 未定义执行者通知，不显示。
- 服务故事：US-02b。

### 设计提案（待确认，非既定需求）
1. 执行者的「我的项目列表」：从「成员登录并进入项目」推导的最低导航承载，不新增业务能力。PRD 定义了成员加入后可进项目，但未单独定义「我的项目列表」故事。
2. 站内通知区：按 PRD 文案设计为全局区域，不先做独立通知页。若后续要历史通知、已读管理，再单独确认。

## 二、主流程（正常路径）

### 流程一 · 负责人核心路径（登录 → 派活）
1. 页1 登录页：输入邮箱密码登录 → 登录成功识别用户 → 跳页3。服务 US-A02。
2. 页3 项目入口：点创建项目入口 → 打开创建界面 → 跳页4。服务 US-P01。
3. 页4 创建项目：填名称提交 → 创建项目，创建者自动成唯一负责人 → 跳页5。服务 US-P01。
4. 页5 项目主页：点进成员页入口 → 进入成员管理 → 跳页9。服务 US-P02、US-P03。
5. 页9 成员页：填邮箱选角色提交 → 成员加入并显示在列表 → 留页9。服务 US-P02、US-R02、US-P03。
6. 页9 成员页：返回项目工作区 → 回项目主视图 → 跳页5。服务 US-P01。
7. 页5 项目主页：点进任务页入口 → 展示任务入口 → 跳页6。服务 US-03、US-01。
8. 页6 任务页：点创建任务入口 → 打开任务创建界面 → 跳页8。服务 US-03、US-08。
9. 页8 任务创建：填标题描述负责人截止日期提交 → 创建并分配任务 → 跳页6。服务 US-03、US-06、US-08。
10. 页6 任务页：新任务出现在全项目列表，状态未开始，负责人和截止日期可见 → 留页6。服务 US-03、US-06、US-02a、US-08。

### 流程二 · 执行者核心路径（登录 → 更新状态）
1. 页1 登录页：输入邮箱密码登录 → 登录成功识别用户 → 跳页3。服务 US-A02。
2. 页3 项目入口：点自己已加入的项目 → 按执行者角色进入项目任务范围 → 跳页6。服务 US-P02、US-07。
3. 页6 任务页：查看「我的任务」，只见分配给自己的任务 → 展示状态/负责人/截止日期/详情入口 → 留页6。服务 US-07、US-06、US-08。
4. 页6 任务页：点某个自己的任务 → 打开该任务详情 → 跳页7。服务 US-07、US-03、US-06。
5. 页7 任务详情：查看标题描述状态负责人截止日期 → 展示状态更新入口 → 留页7。服务 US-07、US-06、US-08。
6. 页7 任务详情：把状态从未开始更新为进行中 → 保存状态，负责人后续可在进度视图看到 → 返回页6。服务 US-07。
7. 页6 任务页：该任务在「我的任务」列表中状态已变进行中 → 留页6。服务 US-07。

## 三、异常流程（非正常路径）

1. 登录失败（邮箱或密码错）：拒绝登录、不建登录态；统一提示「邮箱或密码不正确」不区分字段（防账号枚举）；留页1重输或去页2。服务 US-A02。依据 PRD 登录凭据错误统一提示。
2. 注册失败（邮箱已用）：拒绝创建；提示「该邮箱已被使用」；留页2换邮箱或去页1。服务 US-A01。依据 PRD 注册邮箱已存在规则。
3. 注册失败（密码不符规则）：阻止提交；提示密码规则（至少8位含字母数字）；留页2改密码。服务 US-A01。依据 PRD 密码规则 + D9。
4. 执行者访问负责人专属入口（创建项目/创建任务/成员页）：正常界面不渲染入口；强制访问拒绝操作、不暴露数据、提示「权限不足」；返页3或进页6看自己的任务。服务 US-R01、US-P01、US-03、US-P03。依据 PRD 权限不足规则 + D2。
5. 执行者打开不属于自己的任务：拒绝访问、不展示任务数据、提示「权限不足」；返页6只看自己的任务。服务 US-R01、US-07、US-06。依据 PRD 权限矩阵执行者仅自己的任务 + 权限不足规则 + D6。
6. 邀请成员失败（未指定角色）：阻止提交、不添加成员；提示角色必选；留页9选角色重提。服务 US-R02、US-P02。依据 PRD 添加成员未选角色规则。
7. 邀请成员失败（邮箱重复）：拒绝重复添加；提示已在项目中；留页9换邮箱或结束。服务 US-P02、US-P03。依据 PRD 重复邀请规则。

## 四、三态 UI（加载 / 空 / 错误）

### 页3 项目入口 / 项目列表（服务 US-P01、US-P02、US-05、US-R01）
- 加载态：保留页面框架，身份区与列表区显示骨架占位，不先显示空结论。
- 空态（负责人）：提示还没有项目，引导创建第一个，创建入口可见。
- 空态（执行者）：提示当前无可进入项目，不显示创建入口，说明需负责人添加。
- 错误态：显示列表加载失败区 + 重试入口，不展示半截数据。
- 通用失败文案方向「项目加载失败，请重试」标【设计提案，待确认】。

### 页5 项目主页 / 进度视图（服务 US-01、US-04、US-08、US-R01）
- 加载态：项目名、汇总数字、完成率、成员任务区显示骨架，不提前显示0。
- 空态（负责人）：无任务时汇总显示0，引导去页6或页8创建第一个任务。
- 空态（执行者）：不显示此负责人视图，落到页6我的任务范围。
- 错误态：显示进度加载失败区 + 重试入口，不显示错误完成率或风险提示。
- 通用失败文案方向「进度加载失败，请重试」标【设计提案，待确认】。

### 页6 任务页 / 任务列表（服务 US-03、US-06、US-07、US-02a、US-08、US-R01）
- 加载态：筛选区、任务行、状态、负责人、截止日期显示骨架，角色专属入口在权限确认后再显示。
- 空态（负责人）：提示项目还没有任务，引导创建第一个，创建入口可见。
- 空态（执行者）：提示当前没有分配给你的任务，不显示创建入口。
- 错误态：显示任务加载失败区 + 重试入口，负责人专属管理入口不在错误态中误导操作。
- 通用失败文案方向「任务加载失败，请重试」标【设计提案，待确认】。

### 页7 任务详情页（服务 US-03、US-06、US-07、US-08、US-R01）
- 加载态：标题、描述、状态、负责人、截止日期、操作区显示骨架，加载完成前不显示状态更新控件。
- 空态：不适用（单实体界面）。任务不存在或不可读时，不展示数据，按错误态或权限态处理。
- 错误态：显示详情加载失败区 + 重试入口；权限问题则显示「权限不足」且不暴露数据。
- 非权限类失败文案方向「任务详情加载失败，请重试」标【设计提案，待确认】。

### 页9 项目成员页（服务 US-R02、US-P02、US-P03、US-R01）
- 加载态：成员列表、角色列、邀请区显示骨架，提交入口在角色数据可用后再启用。
- 空态（负责人）：只有创建者本人时不显示空态，显示含创建者的成员列表。
- 空态（执行者）：不显示成员页入口，强制访问提示权限不足、不展示数据。
- 错误态：显示成员加载失败区 + 重试入口，成员数据不可确认时邀请表单不引导继续提交。
- 通用失败文案方向「成员列表加载失败，请重试」标【设计提案，待确认】。

## 五、视觉规范方向（只定方向，精确值留待 Lec 11 前端实现）

### 整体调性
克制、清晰、低干扰的 B 端效率工具。视觉目标不是好看，是让负责人快判断进度、让执行者快知道该做什么。一个页面只突出一个核心任务。

### 调色板取向
以 Tailwind 默认调色板为基础，不单独定制复杂品牌色。中性灰为主 + 一个克制的强调色。理由：核心是状态可读性与责任归属，不需强品牌表达，默认调色板足够支撑首版。

### shadcn 组件选型方向（选型方向，非最终清单）
Button（主要动作）、Input（单行输入）、Textarea（任务描述）、Form（带校验表单）、Select（角色/负责人/状态选择）、Table（任务列表/成员列表/总览）、Card（项目入口/进度汇总/空态承载）、Badge（状态/角色/未认领/卡住标签）、Dialog（创建项目/邀请/建任务等不离上下文操作）、Skeleton（各数据界面加载态）、Alert（登录失败/权限不足/加载失败反馈）、Tabs（任务页同页分区，若用单列表筛选可不用）、DropdownMenu（登出入口、行级轻量操作）。

### 三态视觉统一原则
- 加载态：统一用骨架屏，不用全屏转圈；骨架贴近最终结构，避免布局跳动。
- 空态：放数据区域内部，不全屏打断；负责人给行动引导，执行者只说明无任务/无项目。
- 错误态：优先局部错误块，不崩成空白页；信息短而明确，带重试入口。
- 权限态：无权限入口默认不渲染；强制访问只显示「权限不足」，不泄露数据。
- 状态标签：状态/未认领/卡住/角色用一致徽章体系，强调可扫读，不用大面积高饱和色。
- 风险提示：项目风险和卡住提示比普通状态更醒目但克制，不把页面变成告警面板。
