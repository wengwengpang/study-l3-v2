# REFACTOR-HANDBOOK · 资料重构手册

> 用途：一套给失忆 AI 读的说明书写乱了，要停下来修时，照这份走。
> 来源：study-l3-v2 项目的开课资料重构（2026-09）。文中「补遗 N」指该项目 docs/DECISIONS-G1.md 里的记录，复制到别的项目后只作来历，不用去找。
> 跨项目用：学生亲手复制到 ~/.claude/templates/。CC 不写那里。

## 一、什么时候该停下来修
出现下面任一种，就停下修，不接着用：
- 同一件事写在好几处，改一处漏别处。
- 有句子指向已经作废的东西，读的人只能现编。
- 新会话照旧资料做了一个早已作废的步骤。
理由：每个新会话都读这套说明书，不修，每次都被带歪一点。

## 二、四段流程
- 第一段 · 准备：立工作约定，拍关键裁决，把待办清单更新到最新。做基线提交。
- 第二段 · 修入口：新会话第一个读的文件（读哪些文件、开场做什么）先修对。入口错，后面每步都歪。
- 第三段 · 搬家和删除：内容搬回该在的正本；没用的整节删。
- 第四段 · 收尾：索引定稿，改名后全量扫，跑验证命令，按立项时定的去留处理重构文件（删前扫谁还指着它）。
每段再分组（G0、G1……）。每组开工前做四件：讲这组干什么；列条目让人确认；报要读哪些文件、够不够余量；把每条依据对着现在的文件回核。
每组结束开审查。子代理审只算半独立：和写的人同类模型，盲区可能相同。全部做完，再请一个独立的反方审一遍。

## 三、四份重构文件
立项时就建，立项时就写好去留。会被当出处引用的文件不算临时，要长期留。
- 工作约定：怎么互动、每步节奏、在哪停下。人亲手写。重构结束删。
- 待办清单：每条写状态、依据、判断依据；另有依赖表、执行分组、验证命令。重构结束删。
- 终局图：改完长什么样，哪块搬去哪。执行分组落进待办清单后，它只作来源记录。重构结束删。
- 决策记录：每拍一次板记一条补遗。按组拆成多份，别一份记到底。长期留：规则和原则会拿补遗号当出处；重构结束后只查不追加。
常驻文件尽量不引用要删的文件。非引不可，写明「某文件删除时本句一并删」。

## 四、每一条改动的节奏
1. 我们在哪：第几段、第几组、第几条，还剩几条。
2. 这步干什么：一两句大白话。
3. 为什么改：先打比方，再讲毛病，给出处（文件 + 节 + 原话）。
4. 不改会怎样：举一个具体场景。
5. 新旧对照：原文、改后、影响谁。
6. 停下问同不同意，给「你可以回」。
7. 同意后只用 Edit 定点改。改完用 grep -c 数次数，按预期判：替换是新文 1、旧文 0；搬家第一步复制后旧文仍是 1；纯插入只数新文。
8. 提交，信息带组号和条号，只 add 这一条的文件。
9. 自问：有没有只在对话里的裁决、核查结果、新发现？有就当场落盘。
笼统的「全按你推荐」只放行授权时写进文件的清单条目。清单外的，哪怕改得对，也停下问。清单内遇到 A/B/C 选择、删整节、两份文档打架、改宪法、删文件，也仍然停下问。

## 五、几条硬做法
- 不用脚本改文件，不整份重写。插入时 old_string 带上插入点后面的原文，重跑会失败，不会插第二份。
- 搬家拆两步：先复制，核新家只出现一次，人确认后再删旧家。
- 删前核第二个家；改前扫传播面，逐类写「要改」或「不影响」。
- 写编号前先在正本里查到它。
- 改名用 git mv；合并和改名放同一批，指针只改一次。
- 验证要数次数，不只判存不存在。

## 六、模板
开场报告（每次会话第一件事，自己查 git，不问人）：
```
我们在哪：第几段、第几组；上次做完（提交号）；半截的（没有写「无」）；这次要做
还剩多少：这一段还剩哪几条；后面还有几段
```
补遗（决策记录的一条）：
```
--- 补遗 N · 一句话标题 ---
一，原话：「……」。
二，结论与理由；否决项的理由。
三，执行归属与顺序。
进 HARNESS：新开（原则 N）/ 并入（原则 N）/ 否（换名不成立 | 无出处 | 已覆盖，原则 N | 不是框架层），选其一
```
审查包（每个审查点带三样：改了什么、依据原文、出处）：
```
你是独立审查者，只审不改，挑错为主。
背景 / 要审的 / 依据（出处 + 原文）/ 结论 / 自己不确定的地方
请回答：成不成立？哪里错了？漏了什么？
```
收尾清单（每项写「有（是什么）」或「无」）：没落盘的裁决；没落盘的核查结果；半截的活；新发现的问题；git status 干净吗。

## 七、本场教训
1. 文件立项时就分清临时还是长期。会被当出处引用的文件不是临时文件。决策记录被常驻文件当出处引了几十处，收尾时删不掉，只好专门再定（补遗 130、142）。
   进 HARNESS：并入（原则 11）。待复审。
2. 决策记录按组拆。一份记到两千多行（补遗 130 第五点）。
   进 HARNESS：否（不是框架层）。
3. 审查者起步就建。前半程每组把审查包整段贴去网页版审（工作约定第九节）；中途才改成子代理（补遗 56）。子代理只算半独立，最后另请反方。
   进 HARNESS：新开（原则 16）。待复审。
4. 待记事项拍板时就定落点。「待记 BACKLOG」攒到二十多条，专开一轮清（补遗 127）。
   进 HARNESS：否（不是框架层）。
5. 验证命令也会过期。命令写死了文件路径，改名后得换（所指对象变了）；写在裁决之前的命令，裁决后命中反成预期（依据变了）（补遗 132、138）。
   进 HARNESS：并入（原则 5、11）。待复审。
6. 桥梁另列步骤就会过期。入口文件合并两节后，桥梁里抄的步骤指向了已不存在的节（补遗 138）。
   进 HARNESS：否（已覆盖，原则 1）。
