# 补课 05-API · 速查卡（第一窗口）

## 两条裁决

API-1 · 字段的真相归共享 Zod schema。
契约只写接口层：清单、方法、路径、鉴权级别、退回映射、响应外壳、全局约定。
每个接口点名所用 schema，字段本体留 05-类型。
三份文件各管一段：PRD 管能不能，契约管怎么调，schema 管长什么样。

API-2 · 创建项目不依赖角色。任何已登录用户可建，创建者自动成为负责人。
只挂 AuthGuard，不挂 AuthzGuard。
理由：角色按项目划分，创建时项目不存在，用户没有角色，Guard 要的路径项目 id 也没有。
权限矩阵「创建项目」那一格该标「不适用」，不是改填另一个值。
项目数量上限本版不设，进 BACKLOG 32。

## 三条新规

规则 71 · 编号序列按落点分。落项目文件走项目序列，落课程规则直接编规则号。
规则 72 · 持久文档内部引用不写行号，写小节名。行号只用于当场举证。
规则 57 · 删第 12 项（人工确认权限模式），自检退回 11 项，改机械检查。

## 一条新反模式

43 号 · 把易碎引用写进要长期存活的文档。
行号是位置坐标，文件一增删行就指错，且不同位置偏移量不同，无法统一修复。
判据同 24 号：看这条信息要活多久。

## 四句话记住

两份文档打架，有时不是谁对谁错，是其中一份问了个不成立的问题。
两份需求打架，先看来源：真人确认的比推导的重。
卡住契约不等于属于契约。定完之后它该写在哪个文件，才是落点。
止血和清创是两件事。新规管新写的，存量另开一轮。
