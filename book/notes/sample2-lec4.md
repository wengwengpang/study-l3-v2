## 三、讲法特征

- **固定开头**：每条回复先出「老师锚点 · 3 行」，写分工、红线、这步最可能犯的错（29-32、387-390）。
- **段落九块骨架**：定位 → 为什么 → 核心讲解 → 模式归属 → 终端命令 → CC prompt → prompt 关键点配反例 → 审查清单 → 反馈模板（396-580、636-754）。
- **核心讲解四小步**：3a 原理打比方 → Level 1 对应 → 3b 操作 → 3c 拆开讲 → 3d 联动（412-455、649-687）。
- **先比方后定义，再补一句「不做会怎样」**（645 裁衣服、655；1676 病历、1680）。
- **Level 1 对应是三拍**：网页版时代怎么做 → 痛点 → 现在升级（422-425、659-661）。
- **口吻**：直白口语，短句，一句一行；一个小块约 3 到 10 行，一个完整教学段含命令约 150 到 200 行。重点用粗体，偶尔一句收束的「记法」（1629）。
- **所有决策给选项加推荐加一句理由，并附填空模板**，从不替学生定（823-828、1398-1404）。
- **每个 prompt 后必讲「关键点配反例」**，说明不这样写 AI 会怎么跑偏（549-553、1007-1012）。
- **标明来源**：自己补的内容用 ⚠️ 明说「不是课程原文」（669、924）。
- **学生答错时**：先说对错，引回学生自己立的规则原文，给三行对照记法，再把例子套进去（301-318）。
- **学生追问时**：先纠正问题本身的用词，再比方，再对着已锁约束逐条答，最后收成一句方法论（1577-1584、1623-1629）。
- **学生贴错或输出杂乱时**：列证据，不责备，给补救模板（1273「这不是错…不入库，不扣分」；2944）。
- **自己出错当场认**：数错 11 与 12（3094-3096）；坦白无法替学生核行号（1316）。
- **不轻信「成功」**：学生说已删除仍先验真（2691）；看到「通过」先核内容（1250）。
- 全文没有学生直接说「看不懂」的场面，最接近的是 1569 的暂停提问。3258 的桥梁里老师自述该学生「文字太密会看不懂」。
