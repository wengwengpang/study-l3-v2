# 导读　这本书要做成什么

## 一、这本书教什么，为了什么

这本书带你从零做出一个能上线的网页应用。做的过程里，代码主要由 AI 来写，用的工具叫 Claude Code。

它同时教两样东西。

**第一样：一个真实项目怎么一步步做出来。** 从一个想法开始，依次是需求，设计，选型，写代码，测试，上线，演进。每一步该做什么，该留下什么文件，这本书照着一个真项目走一遍。

**第二样：怎么让 AI 在每一步里可靠地干活。** 规矩写在哪。它能碰什么，不能碰什么。它说做完了，谁来验。出了错怎么修。

**为什么要一起学。** AI 写代码很快。可它不知道你的规矩，也不知道一个项目该按什么顺序做。没有做过项目的人，说不清每一步该要什么，就管不住它。所以只学第二样不够：规矩要落在一个真项目上，才知道管不管用。只学第一样也不够：活是 AI 干的，不会管它，活就走样。

### 学这两样，为的是第三样

第三样是一套换个项目还能用的框架。

这一个工具做完，事情没有完。做的过程里攒下来的规矩、角色、流程、检查办法，要收成一套框架，下一个项目拿来就能用。

框架的中间有一个「中枢」。它不写代码，也不做专业判断。它干四件事：

| 中枢干的事 | 是什么意思 |
|---|---|
| 引导 | 问问题，给选项。拍板的是你 |
| 解答 | 你不懂的，讲到懂 |
| 流程 | 按该有的顺序走，不跳步 |
| 调度 | 安排各个专业角色干活，把上一个的产出交给下一个 |

专业判断交给各个角色，比如管需求的、管设计的、管架构的。角色是什么，第 1 课讲。

它要帮的人，主要是没有任何开发背景的人：说得出「我想做个网站」，说不出该先做什么、后做什么。

**这第三样现在是目标，还没有做成。** 写这一章时，框架的规格里记着十九条已经定下的原则，还列着十六个待答的问题。原则要过一道筛：换个项目仍然成立的才收，每条都注明出处。

三样的关系是这样的：

- 工具是载体。没有一个真项目，规矩是空的。
- 做法是过程里学的。每做一步，都练一遍怎么让 AI 可靠地干活。
- 框架是最后要留下的。每一章的第九节「换个项目还用得上的」，收的就是它的原料。

## 二、这本书写给谁

主要写给没有任何开发背景的人。有技术背景的人也能读。

这本书不假设你会写代码。代码主要由 AI 来写。你要学的是另一些事：把要做的东西说清楚，定规矩，在该你拍板的地方拍板，验收它交的活。

需要你做到的有三样：会用电脑装软件；肯照着书一条一条敲命令；AI 说「做完了」的时候，肯自己去验一遍。

有技术背景的读者，讲网页基础和终端的部分可以跳着看。重点在「怎么管 AI」那一半。

## 三、最后做成什么

一个团队任务协作工具。几个人一起做项目，用它派活、接活、看进度。

### 谁用

两类人。

- **负责人**：派活，看全局，看进度。
- **执行者**：接活，更新进度。

角色是按项目分的。同一个人，在这个项目里是负责人，在另一个项目里可以是执行者。

### 第一版能做什么

| 哪一块 | 能做的事 |
|---|---|
| 账号 | 注册，登录，登出 |
| 项目 | 创建项目，用邮箱邀请成员，给成员分角色，看成员列表 |
| 任务 | 负责人建任务、分给人、设截止日期；执行者看到分给自己的任务，更新状态 |
| 进度 | 每个人的任务状态自动汇到一起；负责人看到整个项目完成了多少 |
| 权限 | 负责人看全项目的任务，执行者只看分给自己的；没权限的操作会被拦下 |

任务有三种状态：没开始，进行中，已完成。

几条已经定下的规矩：

- 登录以后谁都可以创建项目。谁建的，谁就是这个项目的负责人。
- 一个项目只有一个负责人。
- 执行者不能建任务，也不能设截止日期。
- 登录一次管 30 天。
- 密码至少 8 位，要有字母和数字。

### 第一版不做什么

邮件和短信通知，第三方登录，子任务，文件附件，评论，自定义字段和工作流，工时记录，复杂报表，游客只读。

另有两样排在后面：跨项目的总览，任务卡住时的主动预警。

把「不做什么」写下来，和写「做什么」一样要紧。原因在第 2 课讲。

### 长什么样

设计定了十个页面。

| 页面 | 用来干什么 |
|---|---|
| 1 登录页 | 用邮箱和密码登录 |
| 2 注册页 | 新建账号 |
| 3 项目入口页 | 看到自己的项目，从这里进去；登出也在这一页 |
| 4 创建项目 | 填一个项目名，建一个新项目 |
| 5 项目主页 | 负责人看进度：一共多少任务，各种状态各多少，完成了百分之几 |
| 6 任务页 | 任务列表。所有人看任务都从这一页进 |
| 7 任务详情页 | 一条任务的标题、描述、状态、分给了谁、截止日期 |
| 8 创建和编辑任务 | 负责人建任务，分给人，设截止日期 |
| 9 项目成员页 | 负责人看成员，邀请人，改角色 |
| 10 站内通知区 | 给负责人看预警。它不是独立页面，对应的功能排在后面 |

**同一个页面，不同的人看到的不一样。** 拿任务页来说。负责人看到全项目的任务，还有创建和分配的入口。执行者只看到分给自己的任务，还有更新状态的入口。页面只做一套，按角色显示不同的内容。这个做法在第 3 课定下。

**每个取数据的页面要做全三种样子。** 加载中，没有数据，出错。这条规矩叫三态，也在第 3 课定下。第 0 课讲网页请求时会先见到它。

样子的方向是克制、清晰、少打扰：一页只突出一件最要紧的事。具体的颜色和尺寸，到第 11 课写前端时才定。

### 跑在哪

上线以后，它跑在一台租来的服务器上。服务器里有四个容器。容器可以理解成各自独立的小房间，一个房间跑一个服务。

| 容器 | 干什么 |
|---|---|
| Nginx | 对外唯一的入口。接住所有请求，按路径分给前端或后端 |
| 前端 | 生成你在浏览器里看到的页面 |
| 后端 | 核对你是谁、能做什么，处理数据 |
| 数据库 | 存数据，一共六张表 |

**前端和后端是什么。** 前端是你在浏览器里看得见、点得着的那一部分。后端是服务器上的那一部分程序。你看不见它。它负责核对你是谁、能做什么，再去读写数据。

用到的技术，名字先见一面，后面各章会讲：

| 用在哪 | 选的是什么 |
|---|---|
| 写代码的语言 | TypeScript，前端后端都用它 |
| 前端 | Next.js，Tailwind CSS，shadcn/ui |
| 后端 | NestJS |
| 数据 | PostgreSQL 数据库，用 Prisma 读写 |
| 核对数据的格式 | Zod，前端后端共用一份规则 |
| 部署 | 一台服务器，Docker Compose 管四个容器，Nginx 在最外面 |

为什么选这些，第 4 课讲。

### 现在它做到哪了

写这一章时，这个工具还没有一行业务代码。仓库里和它有关的，是一批设计文件，加一份数据库的结构定义。

这不是进度慢，是这本书的做法：先把设计做完，再写代码。理由在第 0 课。

## 四、全流程地图

全书六篇，对应做一个项目的六个阶段。

| 篇 | 哪几课 | 进来什么 | 出去什么 | 过关点 |
|---|---|---|---|---|
| 第一篇　立项准备 | 第 0 到 6 课，加四节补课 | 一个想法 | 一整套设计文件，一本规则书，一道权限墙 | 无 |
| 第二篇　环境搭建 | 第 7 到 9 课 | 设计文件 | 一个能跑起来的空架子 | SG-1 |
| 第三篇　MVP 开发 | 第 10 到 12 课 | 空架子 | 最小可用版本 | SG-2 |
| 第四篇　功能扩展 | 第 13、14 课 | 最小可用版本 | 功能做全，有测试，过了安全检查 | SG-3 |
| 第五篇　部署上线 | 第 15 到 17 课 | 在自己电脑上能跑的系统 | 线上能访问，能自动检查和部署，有监控 | SG-4、5、6 |
| 第六篇　演进考核 | 第 18、19 课 | 线上的系统 | 做成一次真实的改动；独立做完三道题 | 无 |

### 六篇各做什么

**第一篇　立项准备。** 一行业务代码都不写。先弄清给谁用（第 1 课），做什么、不做什么（第 2 课），长什么样（第 3 课），用什么技术（第 4 课），数据怎么存（第 5 课）。四节补课接着定四件事：系统怎么分块，前端和后端之间怎么对话，两边共用哪些定义，开发和上线的环境怎么配。第 0 课和第 6 课管的是 AI：第 0 课立规则书的第一层；第 6 课定下什么事 AI 必须停下来问，什么动作由机器直接拦。

**第二篇　环境搭建。** 把写代码的地方搭好。第 7 课建仓库的骨架：前端、后端、两边共用的代码，放进同一个仓库。这种放法叫 Monorepo。第 8 课配提交前的自动检查，再故意写错一次，看它拦不拦得住。第 9 课用 Docker 把数据库跑起来，灌进一批样例数据。Docker 是把服务装进容器的工具。

**第三篇　MVP 开发。** MVP 是最小可用版本：功能最少，但从头到尾能用。第 10 课写后端，第 11 课写前端，第 12 课把两边接起来。

**第四篇　功能扩展。** 第 13 课把剩下的功能做全。第 14 课建测试，做安全检查。

**第五篇　部署上线。** 第 15 课把系统放到服务器上，配域名和加密，再做一次灾备演练。灾备演练就是假装数据丢了，练一遍怎么恢复。第 16 课配 CI/CD：代码一提交，机器自动检查；通过了，自动部署。第 17 课配监控，出了问题有告警送到人。

**第六篇　演进考核。** 第 18 课对线上的系统做一次真实的改动，照「先加新的，再迁数据，最后删老的」三步走。第 19 课独立做完三道题。

### 过关点

过关点的英文是 Stage Gate，简称 SG。一共六个。到了过关点，不看谁说做好了，看机器验出来的结果。

| 过关点 | 在哪一课 | 验什么 |
|---|---|---|
| SG-1 | 第 7 课 | 前端和后端各跑出一个最小页面，浏览器能看到 |
| SG-2 | 第 12 课 | 最小可用版本从头到尾能跑通 |
| SG-3 | 第 14 课 | 测试覆盖率达标，安全检查通过 |
| SG-4 | 第 15 课 | 正式域名加 HTTPS，灾备演练做过 |
| SG-5 | 第 16 课 | 故意弄坏一次，自动流程能拦住；能自动部署 |
| SG-6 | 第 17 课 | 监控齐全，告警能送到人 |

表里写的是每个过关点验哪一类事。具体用什么命令验、到什么程度算过，在它所在的那一课定。

第一篇和第六篇没有过关点。第五篇有三个。

## 六、读之前要准备什么

- **一台电脑。** 书里的命令是在 Windows 11 上跑的，用的是里面的 WSL2 和 Ubuntu 22.04。用 macOS 或 Linux 也可以，跳过和 WSL 有关的部分。
- **三样软件。** Git，VS Code，Claude Code。
- **一个能登录 Claude Code 的账号。** 官方写的有三种：Claude 的订阅（Pro、Max、Team、Enterprise），Claude Console 账号（预付费，按用量算），或者经由受支持的云服务商。价格看官方的定价页。
- **到第五篇才要的。** 一台服务器，一个域名。现在不用准备。

这本书不讲怎么安装。安装步骤会随版本变，各家的官方安装页才是准的。第 0 课第四节有一张表，每样东西配一条命令，敲一下就知道装好了没有。

没用过终端也不要紧。终端就是敲命令的那个窗口。第 0 课第四节从「在哪敲命令」讲起。Claude Code 的官方文档里，也有一页专门写给没用过终端的人。

## 七、这本书怎么读

**章号就是课号。** 这本书跟着一门课一课一课写成，章号沿用课号。所以第一章叫第 0 课，中间还有四节「补课」。

**每一章都是同样的十节。**

| 节 | 讲什么 |
|---|---|
| 一、本章位置 | 在地图上第几步。上一章交来什么，这一章产出什么，下一章拿它做什么 |
| 二、学完能做到什么 | 三到五条，都能检验 |
| 三、原理 | 为什么要有这一步，不做会怎样 |
| 四、动手 | 一步一步做。每步有目的，要敲的命令或要发的 prompt，应该看到什么，出了错怎么办 |
| 五、产出物 | 这一章留下的文件，关键内容的原文 |
| 六、Claude Code 知识点 | 这一章第一次用到的功能 |
| 七、常见的坑 | 踩过的坑，怎么防 |
| 八、小结与速查 | 要点和用到的命令 |
| 九、换个项目还用得上的 | 这一章里能带走的做法，是那套框架的原料 |
| 十、本章依据 | 出处，核对日期 |

**两种读法。** 想照着做的，从第 0 课起顺着读，每章的第四节跟着敲。只想弄懂道理的，读每章的第三节和第八节。

**附录。** 一共七份：Claude Code 速查，协议与模板，角色一览，反模式索引，术语表，产出物总表，课程沿革。写这一章时，附录还没有写。

**几个记号。**

- 底色深一点的方块里，是要原样敲的命令，或者要原样发给 AI 的话。
- 「应该看到」后面的内容，是照着做的时候屏幕上该出现的东西。
- 标了「示意」的例子，是为了讲清楚而设的，不是这个项目里发生过的事。没标的是真发生过的，章末有出处。
- 「本项目」指那个团队任务协作工具。
- prompt 指你发给 AI 的那段话。
- CC 是 Claude Code 的简称，只出现在引用的原文里。
- SG 是过关点。

**书里的事实都给了出处。** 每章最后一节写着出处和核对的日期。没有实际操作过的步骤，标着「待实测」；不是真实输出的例子，标着「示意」。Claude Code 更新得快。书里关于它的说法，对的是核对那一天的官方文档。你读到的时候如果和屏幕上不一样，以官方文档为准。
