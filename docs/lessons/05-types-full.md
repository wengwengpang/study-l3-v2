## 第一窗口（2026-11-05，R1-705 到 R1-720）

### 这节在做什么

契约点了 schema 的名字，这节把字段交出来。比方是菜单和配方：契约是菜单，只写菜名；schema 是配方。前后端是两个厨房，共用一本配方书，字段名才不会对不上。

### 做到哪

开课走完，核对轮、起草轮都跑了，47 条未决加 4 条文档冲突，拍到只剩两条（C11、N26）。起草稿实跑全过，还没落盘。回写、书章、结课留后面。

### 学到的能力

- 先派只读角色把契约和需求、表、页面对一遍，拿回能逐条拍板的未决清单，再动笔。
- 让角色起草代码，配上它自己写的样例，由机器验，不靠它说「完成」。
- 验证之前先验验证本身：故意改坏，看样例抓不抓得到。

### 查证翻出来的事

这些都是主对话实跑或读原文查出来的，架构师读不了网页和包，有的它写错了，有的它想不到。

- Zod 4.6.7 的长度按 Unicode 码点算，不是 JS 长度，翻了 N12 的前提。
- `min(1).trim()` 放过全空白、存空串，必须先 trim。
- 并集里执行者形状排在前面，负责人那份的专属项会被丢。
- TypeScript 不拦从变量返回的多余字段，`return user` 能把 passwordHash 带出去。所以响应要过 schema。
- NestJS 12.0 起有内置校验管道和内置出参拦截器，推翻了 05-ARCH 的「自写管道」。拦截器的 schema 按路由固定，分不了角色。
- Zod 默认邮箱格式拒中文地址，预设 unicodeEmail 不拒。
- Zalando #240 要枚举大写。库没建，现在改最便宜，学生选全链路大写。
