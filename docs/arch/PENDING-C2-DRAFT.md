## 一、接口清单骨架

一共 17 个接口。notifications 模块本版没有接口（API-45，docs/arch/API_CONTRACT.md:484）。authz 是横切模块，也没有接口（docs/arch/ARCHITECTURE.md:32-39）。表里写「候选」的路径都还没定，后面括号写着去第四块哪一条。

**鉴权四档**
- 公开：不挂 AuthGuard。
- 只要登录：只挂 AuthGuard。
- 本项目成员：AuthGuard 加 AuthzGuard，两种角色都放行。
- 只有负责人：AuthGuard 加 AuthzGuard，执行者回「不许做」。

**每行都不再重复写的退回**
- 所有接口都可能回「内部错误」。路径不存在算「看不见」（docs/arch/API_CONTRACT.md:207-209）。
- 所有非 GET 都可能回「跨站被拒」（:75-77）。
- 带请求体的都可能回「格式不支持」和「参数不合法」（:101、:111-117）。
- 所有 GET 碰到多出来的查询参数，回「参数不合法」（:117）。
- 除了两个公开接口，都可能回「未登录」。
- 路径带项目 id 的，不是成员或 id 转不成数字时回「看不见」（:55）。

**路径用到的标准**

以下三条都已登记在 docs/arch/STANDARDS.md:33。
- Zalando #129，路径小写、单词用连字符。必须（API-51 第六点）。

- 未登录：公开接口以外的全部接口（API-14）。
- 跨站被拒：GET 以外的全部接口。专门的 type（API-11、API-29）。
- 格式不支持：带请求体的全部接口（API-27）。
- 参数不合法：带请求体的全部接口。有四种：形状或类型不符；多出 schema 没列的字段，含请求体多带项目 id；必填项去空白后为空；请求体不是合法 JSON（API-14、API-31、API-32、API-47、决策 D）。GET 接口带了 schema 没定义的查询参数，也回这一种。本版 GET 接口都不收查询参数（API-56）。
- 冲突：写接口在并发下撞上数据库唯一约束（API-28）。注册、邀请成员撞上的约束，就是它们各自那一种冲突，回同一个专门的 type（推导）。

### 3. schema 名字

- 只定名字主体。写不写后缀，照 05-类型 为全部 schema 定的命名规则（API-1、API-30）。
- 请求体的名字写成「动作 + 资源 + Request」。动作跟着方法走：POST 写 Create，PATCH 写 Update，PUT 写 Replace（待确认（假设））。
- 响应用资源名。列表的外壳在资源名后加 List。数组放在外壳的哪个字段里，归 schema（API-18）。
- 列表的每一项与这个资源的详情同一形状，用同一个名字（待确认（假设））。
- 一个资源按调用者角色给不同形状时，仍用一个名字。几种形状在 schema 里怎么写，归 05-类型（待确认（假设））。
