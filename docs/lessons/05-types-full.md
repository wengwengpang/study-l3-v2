- 验证之前先验验证本身：故意改坏，看样例抓不抓得到。

### 查证翻出来的事

这些都是主对话实跑或读原文查出来的，架构师读不了网页和包，有的它写错了，有的它想不到。

- Zod 4.6.7 的长度按 Unicode 码点算，不是 JS 长度，翻了 N12 的前提。
- `min(1).trim()` 放过全空白、存空串，必须先 trim。
- 并集里执行者形状排在前面，负责人那份的专属项会被丢。
- TypeScript 不拦从变量返回的多余字段，`return user` 能把 passwordHash 带出去。所以响应要过 schema。
- NestJS 12.0 起有内置校验管道和内置出参拦截器，推翻了 05-ARCH 的「自写管道」。拦截器的 schema 按路由固定，分不了角色。
- Zod 默认邮箱格式拒中文地址，预设 unicodeEmail 不拒。
- Zalando #240 要枚举大写。库没建，现在改最便宜，学生选全链路大写。

### 查证翻出来的事

- 邮箱上限 254 是按字节量的：RFC 5321 写长度按字节计，路径上限 256 含一对尖括号，勘误 1690 写 254。所以按字节判，不按码点。
- RFC 9457 的例子里 type 末段是小写加连字符；Zalando #240 要大写的是枚举，错误类型不在它管的范围里，登了偏离。
- 自起的 URN 命名空间没在 IANA 登记，照 RFC 8141 第 1 节不算正式 URN，登了偏离。
- tsc 不设 lib 时默认带 DOM，TextEncoder 才认得；只带 es2022 会报找不到。
- NestJS 的内置管道认任何兼容 Standard Schema 的库，官方点名 Zod；Standard Schema 与变异测试补登进标准登记表。
- 第 5 课那章产出物开头写「schema 自建成以来没有改过」，05-API 改过三次后没跟上，这次改正。
- 决策记录 R1-460 引「规则 76」作「先落 ADR」的依据，号和内容对不上；规则书里没有「先落 ADR」的正本。
