## 设计内容要点

### 页面结构（10 页）
登录 / 注册 / 项目入口（跨项目总览）/ 创建项目 / 项目主页（负责人进度视图）/ 任务页（统一入口）/ 任务详情 / 任务创建编辑 / 项目成员页 / 站内通知区（P2 延后）。
每页标了访问层级（公开 / 需登录 / 按角色）和服务的 US 编号。

### 任务入口决策（D6）
采用「单页面 + 按角色条件渲染」。一个任务页，负责人渲染全项目任务 + 创建/分配入口，执行者只渲染「我的任务」+ 状态更新。不做两套独立页面。
理由：保持「任务统一入口」产品心智，用权限控制数据范围，避免维护两套重复页面。

### 主流程（2 条）
负责人核心路径：登录 → 建项目 → 邀成员 → 建任务并分配 → 任务进待办。
执行者核心路径：登录 → 进项目 → 看我的任务 → 打开 → 更新状态。
每步标了页码（1-10）+ 系统反馈 + 跳转 + US 编号。

### 异常流程（7 条）
登录失败、注册失败（邮箱已用 / 密码不符）、执行者越权访问负责人页、执行者越权打开他人任务、邀请失败（缺角色 / 邮箱重复）。
每条标 US + PRD 错误/边界规则依据。

### 三态 UI（5 个数据界面）
页 3/5/6/7/9 各定加载态 / 空态 / 错误态。
核心铁律：
- 加载态统一骨架屏，不全屏转圈。
- 空态区分角色——负责人给行动引导，执行者只说明暂无。
- 错误态优先局部块 + 重试，不崩全屏；权限错只提示「权限不足」不暴露数据。
- 单实体界面（任务详情）无空态，缺数据按错误/权限态处理。
- 通用「请求失败」文案 PRD 未定义，标为「设计提案，待确认」，只定结构方向。

### 视觉方向（精确值留 Lec 11）
克制清晰的 B 端效率工具。Tailwind 默认调色板 + 中性灰为主 + 一个克制强调色。Tailwind + shadcn 组件栈，列了 13 个核心组件选型方向。

## 口径裁决（本课关键决策）
PRD 自相矛盾：US-03/US-06 宽措辞（所有成员看所有任务）对不上权限矩阵（执行者只看自己）。
裁决：以权限矩阵 + D1-D9 为准，宽措辞按角色收敛。PRD 原文不改，加澄清注记。
designer 撞见矛盾时主动停下等拍板，没谄媚硬画（反模式 16 的正面）。
