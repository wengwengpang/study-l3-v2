# 第 0 课　全局观

## 这一课解决什么问题

第 0 课一行业务代码都没写。它只回答三个问题：

1. 你现在学的这套东西，在整个行业里处在什么位置？
2. 后面所有规矩，是从哪几句话里长出来的？
3. 这趟路一共多长，中间有哪些站？

这三个问题是一条因果链。老师的原话是：**认知，原则，路线。**

先看清自己站在哪（认知），才明白这门课为什么这么设计。再立三句信仰（原则），后面每条规矩都能追到这三句。最后看全景图（路线），知道这三句话是怎么铺在二十节课里的。

这一课还顺手做了几件打地基的事：建了宪法的第一层，建了反模式库，做了第一次提交，第一次让 CC 干活。

## 第一部分　三层楼

### 爬楼梯

教 AI 干活这件事，这几年像爬楼梯，一年一层。

**第一层，2024 年，叫 Prompt Engineering。** 研究的是「怎么问」。同一个问题换个问法，AI 答得好坏差很多。大家琢磨的是单条消息怎么写。

**第二层，2025 年，叫 Context Engineering。** 研究的是「给它看什么」。人们发现光会问不够，还得控制 AI 面前摆着哪些资料：对的文档，对的代码片段，对的历史对话。

**第三层，2026 年，叫 Harness Engineering。** 研究的是「给它搭一个什么样的工作环境」。这是你现在站的地方。

一句话区分这三层：

- Prompt 是你说的那句话。
- Context 是它眼前摆的资料。
- Harness 是它整个工作间的布置。

### 用同一件事看三层的差别

下面这个例子是我为了讲清楚编的，不是课上的原话。

你想让 AI 的每次提交都用规范的提交信息。

在第一层，你的办法是每次都说一句：「提交信息用 Conventional Commits。」哪次忘了说，它就乱写。

在第二层，你的办法是把一份提交规范文档贴给它看。它这次会照做。换一个新会话，你得再贴一遍。

在第三层，你把这条规矩写进 CLAUDE.md。CC 每次进项目自己会读到，你一个字都不用说。将来还可以再加一道自动检查，提交信息不合格就提交不上去。

三层解决的是同一件事。区别在于：你的叮嘱，是每次都要重说，还是说一次就一直生效。

### Harness 这个词

Harness 的字面意思是马具，就是套在马身上的那套装备。马有力气，马具让力气用在对的方向上。

放到这门课里，它指的是你给 AI 搭的整套工作环境：规则书在哪，它能碰什么不能碰什么，它干完活谁来验证，出了错怎么修。

### 核心思想：把叮嘱变成环境

这是老师给 Harness 下的一句话定义，也是贯穿整门课的主线。

打个比方。

一个糟糕的老板，每件事都得盯着员工，反复交代「记得这样，别那样」。他一走开，事情就走样。

一个好老板，把规矩写进员工手册，把流程做成自动检查。然后他不用盯，员工自己就能做对。

Harness Engineering 教的是当后一种老板，对象是 AI。

### 这门课建的东西，对到 Harness 上

你后面建的每样东西，都是「把一句叮嘱变成环境」。

| 你建的东西 | 它替掉的那句叮嘱 | 现在有了吗 |
|---|---|---|
| CLAUDE.md | 「记住我们项目的规矩」 | 有，三层都建了 |
| 决策边界 | 「这种事先问我」 | 有，第 6 课建 |
| `.claude/settings.json` | 「这个命令别乱跑」 | 有，第 6 课建 |
| 角色文件 | 「你现在是产品经理，只管需求」 | 有，现在六个 |
| 反模式库 | 「这个坑上次踩过，别再踩」 | 有，现在 46 条 |
| 自动检查命令 | 「改完记得跑一遍检查」 | 还没建，后面的课 |

所以老师说，这门课真正的产出不是一个任务协作工具，是一套完整的 Harness。工具做完就做完了。会搭 Harness，换一个项目还能再搭一次。

## 第二部分　三大信仰

这三句话写在 CLAUDE.md 最前面。后面所有规矩都是从它们长出来的。

### 信仰一：宪法先于代码

**意思。** 规则书先写好，再写代码。

**为什么。** AI 写代码极快，可它不知道你的规矩。不先立规矩，它就按自己的习惯来：命名乱，提交信息乱，该问你的不问。等代码写了一堆再回头立规矩，前面写的都要返工。

**这个项目里的样子。** 前六课没有写一行业务代码，全在做设计：做什么，给谁用，长什么样，用什么技术，数据怎么存。这不是拖时间，这就是这条信仰本身。

老师还提过上一个作废项目的教训：那次是第 1 课上到一半，踩了坑，才慌忙回头补宪法。

### 信仰二：验证先于信任

**意思。** AI 说「做完了」不算。人说「应该没问题」也不算。机器跑一遍检查，全部通过，才算。

**为什么。** AI 有个毛病：它会很自信地说「代码应该能工作」。可是「应该能」和「验证过能」是两回事。它不是故意骗你，它只是没去跑。

**这个项目里的样子。** 最清楚的一次在第 6 课。权限文件建好了，你在验证清单上写的是「没测，格式完全正确，实际跑必定是对的」。老师把课停了下来，让你真去跑 `/permissions`。屏幕上显示三种牌子都加载了，那一项才算过。详细经过在第 6 课那一章。

重温题里你选的是「看到测试命令的真实输出是全绿的」，这就是这条信仰的用法：不信嘴，信输出。

### 信仰三：演进先于完美

**意思。** 不追求一步到位的完美设计，追求随时能改。

**为什么。** 需求一定会变。一个改不动的完美设计，撑不过第一次变更。

**具体怎么做。** 有一个三步的口诀：先加新的，再把数据迁过去，最后才删老的。英文叫 Expand，Migrate，Contract。

举个例子。这个场景是假设的，项目里还没发生。

任务表里有一个字段存「负责人的名字」。后来你想改成存「负责人的用户编号」。

莽的做法是直接把老字段改掉。改的那一瞬间，所有还在读老字段的代码全部报错。

三步走的做法是这样的：

1. **先加新的。** 表里加一个新字段存用户编号。老字段不动，老代码照常跑。
2. **再迁数据。** 把老字段里的名字，一条条对应成编号，填进新字段。同时把代码逐步改成读新字段。
3. **最后删老的。** 确认没有任何代码还在读老字段了，才把它删掉。

每一步做完，系统都是能跑的。哪一步出了问题，退回上一步就行。

这个口诀课程安排在第 18 课真做一次。第 0 课只要有个印象。

## 第四部分　一个请求的一生

### 为什么第 0 课就讲这个

你以后让 CC 写的每一行代码，都落在这条线的某一段上。

审 CC 的代码时，先问一句「它在第几步动手」，定位就快了。出了问题，也是先问「卡在第几步」。

课上这部分是快速回顾，九步各一行。下面比课上讲得细。展开的部分依据的是这个项目的架构文档，加上通用的网络知识。

### 一个贯穿九步的比方

把这件事想成你去一栋写字楼办事。

你要办的事是：执行者小王在浏览器里点开一条任务，想看它的详情。

### 第 1 步　查地址

**发生了什么。** 小王在浏览器里用的是域名，一串好记的字。可网络只认数字地址，叫 IP。浏览器要先把域名换成 IP。负责做这个翻译的系统叫 DNS。

**比方。** 你只知道写字楼叫什么名字。出发前先查地图，查到它在哪条街几号。

**出了错长什么样。** 浏览器直接说「找不到这个网站」。请求连门都没出。

### 第 2 步　建一条安全的通道

**发生了什么。** 浏览器和服务器先连上线，这叫 TCP 连接。接着双方商量好一套加密办法，这叫 TLS 握手。网址开头 HTTPS 里的那个 S，指的就是这一步。

**比方。** 你到了楼下，不是站在街上喊话。你和楼里的人先拉了一条密封的专用管道，之后的东西都从管道里递，路人看不见。

**出了错长什么样。** 浏览器弹出证书警告，说这个连接不安全。

### 第 3 步　递申请单

**发生了什么。** 浏览器发出一个 HTTP 请求。这张「申请单」上写着四样东西：

- 方法：要干什么。看东西是 GET，新建是 POST。
- 路径：要找哪样东西。
- 请求头：一些附带信息，其中包括能证明「我是谁」的凭据。
- 请求体：要提交的内容。看详情不用提交内容，所以这次是空的。

凭据具体怎么带，这个项目还没定，是 05-API 的待决项。

**比方。** 你把填好的申请单从管道里递进去。

### 第 4 步　前台分流

**发生了什么。** 请求到了服务器，第一个接手它的是 Nginx。重温题里你答对的就是这一步。

Nginx 在这个项目里只做两件事。

一是把第 2 步的加密拆开。加密到 Nginx 为止，里面各个服务之间不用再加密一遍。

二是看路径分流。路径以接口前缀开头的，转给后端。其余的，转给前端。

这种站在最前面替别人收请求的角色，叫反向代理。

**比方。** 写字楼的前台。她不办具体业务，只看你的单子，告诉你去几楼哪个窗口。

**出了错长什么样。** 后端没启动的时候，Nginx 找不到人转交，会回一个 502。看到 502，问题多半不在你的业务代码里，在「后面的服务没起来」。

### 第 5 步　保安查证件

**发生了什么。** 请求进了后端，先过守卫，代码里叫 Guard。这个项目有两个守卫，各问一句话。

- 第一个问：你登录了吗？
- 第二个问：你在这个项目里是什么角色，够不够格？

被守卫拦下，后面几步全都不执行。

课上讲这一步时，举的例子是 JWT。那时技术选型还没做。到第 4 课定下来的是另一种：登录状态存在数据库里，叫 session。原因是需求要「登出立刻失效」「角色改了立刻生效」，这两样都要服务器自己手里握着状态。

**比方。** 楼层入口的保安。先看你有没有工牌，再看你的工牌能不能进这一层。

**出了错长什么样。** 页面显示「权限不足」。这个项目有个特别的规定：「没权限」和「这条任务不存在」回的是同一个结果。这样外人试不出某条任务到底存不存在。

### 第 6 步　窗口核对，然后办事

**发生了什么。** 过了守卫，还有三站。

- 校验：检查请求里的数据合不合格式。这个项目用的是 Zod，前端和后端共用同一份规则。
- 控制器：接待请求，决定交给谁办。代码里叫 Controller。
- 业务逻辑：真正干活的地方。代码里叫 Service。

**比方。** 窗口的人先看你的表格填没填对。填对了，交给后面的办事员去办。

### 第 7 步　去档案室

**发生了什么。** 业务逻辑需要数据，就去读写数据库。这个项目的数据库是 PostgreSQL。代码不直接写数据库的语言，通过一个叫 Prisma 的工具去读写。

**比方。** 办事员拿着你的单子，去档案室把那份档案调出来。

### 第 8 步　写回执

**发生了什么。** 后端把结果装成一个响应，原路发回去。响应里有一个状态码，告诉浏览器这次是成了还是没成，没成是哪一类。

响应具体包成什么形状，是 05-API 的待决项。

**比方。** 办事员写好回执，从窗口递出来，经过前台，从管道送回你手里。

### 第 9 步　你看到结果

**发生了什么。** 浏览器收到响应，把页面画出来。

这一步有三种样子，叫三态。这个项目对三态有硬规定：

- 加载中：显示骨架屏，就是一块块灰色的占位，不用整屏转圈。
- 成功：显示内容。没有内容时显示空态，而且空态要分角色。
- 出错：在出错的那一块显示错误和重试按钮，不能整屏变白。

**比方。** 你拿到回执，看上面写了什么。

### 九步连起来

| 步 | 发生了什么 | 这个项目里是谁 |
|---|---|---|
| 1 | 域名换成地址 | DNS |
| 2 | 建加密通道 | TCP 与 TLS |
| 3 | 发出请求 | 浏览器 |
| 4 | 拆加密，分流 | Nginx |
| 5 | 查登录，查角色 | 两个 Guard |
| 6 | 校验，接待，办事 | Zod，Controller，Service |
| 7 | 读写数据 | Prisma 与 PostgreSQL |
| 8 | 装好结果发回 | 后端 |
| 9 | 画出页面 | 浏览器 |

第 4 步之前的事，到第 15 课部署时才会碰。第 5 到第 8 步是第 10 课写后端的主战场。第 9 步是第 11 课写前端的事。

## 第五部分　这一课动手做的事

### 命令在哪里敲

这是你课上问的第一个问题。

你的电脑里其实住着两个系统。Windows 是主人。Ubuntu 是租客，跑在一个叫 WSL2 的东西里。

项目放在租客的房间里，路径是 `~/projects/`。所以所有命令都要在 Ubuntu 的终端里敲，不是 Windows 的 PowerShell。

`~` 这个符号在 Ubuntu 里指你的家目录。在 PowerShell 里它不是这个意思。命令敲错了地方，路径就全错。

怎么确认站对了地方：敲 `pwd`。显示 `/home/michael` 开头就对了。显示 `/mnt/c/` 开头，说明你站到主人那边去了。

### VS Code 和 Claude Code 是两样东西

VS Code 是看文件、改文件的编辑器。

Claude Code 是在终端里跑的那个 AI 工具，简称 CC。

两个配合着用：CC 改文件，你在 VS Code 里看它改了什么。

VS Code 默认站在 Windows 那边。要让它走进 Ubuntu 的房间，得「连上 WSL」。连没连上，看窗口左下角：有一个写着 `WSL: Ubuntu` 的小标，就是连上了。

### CLAUDE.md 是一本公司手册

新员工入职第一天，活还没开始干，先发一本公司手册。手册里写的是做事的规矩：怎么提交，怎么引用，什么不许干。它不讲某一桩具体业务。

CLAUDE.md 就是发给 CC 的这本手册。CC 每次进项目都会自动读它。

它分三层，是分三个时候建的。

- 第一层：通用规矩，加上上一个项目踩过的 13 个坑。和具体项目无关，所以第 0 课就能定。
- 第二层：项目事实。第 1 到 5 课，每定下一样就填一样。
- 第三层：决策边界。第 6 课建。

为什么第一层要在第 0 课就建？因为它不依赖项目，现在就能定。等踩了坑再建就晚了。

### 同样 13 条，为什么放两个地方

那 13 个坑，CLAUDE.md 里写了一遍，`docs/lessons/anti-patterns.md` 里又写了一遍。这不是重复，两份是给不同的读者看的。

CLAUDE.md 里那份是给 CC 看的。它每次都要读，所以每条只有一两句。

反模式库那份是给你攒经验用的。每次真踩了新坑，就往里加一条，写清现象、根因、怎么修、教训是什么。它会越来越厚。第 0 课时是 13 条，现在是 46 条。

这和第 6 课讲的「同一套内容，两个读者」是同一个道理。

### 第一次提交

宪法和反模式库建好以后，做了这个仓库的第一次提交。

为什么这时候就提交？这两份是地基文件。存进版本库以后，以后任何改动都能对比，改坏了能退回去。

提交信息的格式有规定，叫 Conventional Commits。写法是「类型，冒号，简短描述」。这次的类型是 `chore`，意思是杂务。

### 第一次让 CC 干活

课的最后，你第一次启动 CC，让它写这节课的两份笔记。

这里有一个很要紧的认识：**CC 不在你和老师的对话里。**

你和老师在网页上聊了一节课。CC 在你电脑的终端里。它一个字都没听到。

如果你只对它说「写一份第 0 课的笔记」，它会凭「第 0 课」「全局观」这几个字自己编，写出来的东西和实际讲的对不上。

所以那条指令做了两件事。

开头就告诉它：你不在我的上课对话里。然后把这节课的要点一条条列给它。

结尾要求它：逐条告诉我文件建在哪、写了多少字，不要只说一句「完成了」。这是信仰二的用法。

这个坑排在 13 条里的第 1 号：假设 AI 知道我没说过的事。

## 课上你提的意见，后来成了规矩

这一课后半段，你一共提了十几条意见。下面几条到现在还在用。

- **先讲为什么，再讲内容。** 你问老师：为什么讲这三件事？老师才补上「认知，原则，路线」那句话。从此每一段开头都要先说清这几件事的关系。
- **字数给范围，不给死数。** 要求「正好 500 字」，CC 会为了卡线反复数、反复删，白白耗掉很多用量。
- **切模式是你按键的事。** 不要在指令里写「请切到某某模式」。模式是你在键盘上切的，不是 AI 自己能切的。
- **不给没有终点的指令。** 「反复优化直到完美」没有停止条件，AI 可能停不下来。
- **规矩存进文件，不靠口口相传。** 一开始新规矩是写在给下一节课的交接文字里往下传的。你指出来：传几次就走样了。后来规矩都存进了固定的文件。
- **AI 编的用户不是真用户。** 你提议让两个 AI 角色互相问答来做用户研究。老师指出一个漏洞：AI 凭空编需求，再把编的东西当成研究结论。这直接决定了第 1 课怎么设计，下一章讲。

## 一页速查

- 三层楼：Prompt 是你说的那句话，Context 是它眼前的资料，Harness 是它整个工作间的布置。
- Harness 的核心思想：把每次都要叮嘱的话，变成环境里配好一次的设置。
- 信仰一，宪法先于代码：规矩先立，代码后写。
- 信仰二，验证先于信任：不信嘴，信机器跑出来的输出。
- 信仰三，演进先于完美：先加新的，再迁数据，最后删老的。
- 过关点是骨架，课数有弹性。
- 一个请求走九步：查地址，建通道，发请求，Nginx 分流，守卫，校验与办事，数据库，回响应，画页面。
- 请求到服务器，第一个接手的是 Nginx。
- 看到 502，先想「后面的服务没起来」。
- 命令在 Ubuntu 终端里敲。`pwd` 显示 `/home/` 开头才对。
- CLAUDE.md 是发给 CC 的公司手册，分三层，分三个时候建。
- CC 不在你和老师的对话里。要它干活，先把它需要知道的喂给它。

## 自测

**第 1 题。** 你发现自己每次开新会话，都要提醒 CC「回答用中文」。下面哪种做法属于 Harness 那一层？

- A　把这句话写得更强硬一点。
- B　把语言规矩写进 CLAUDE.md。
- C　每次开会话先贴一份语言说明文档。

**第 2 题。** 页面打不开，浏览器显示 502。按九步来看，最该先查哪里？

- A　前端页面的代码。
- B　数据库里的数据。
- C　后端服务有没有启动。

**第 3 题。** 小王没登录，直接访问一条任务的地址。请求会停在第几步？

- A　第 4 步，Nginx。
- B　第 5 步，守卫。
- C　第 7 步，数据库。

**第 4 题。** 要把一个老字段换成新字段。按「演进先于完美」，第一步做什么？

- A　删掉老字段。
- B　加上新字段，老字段先留着。
- C　停机，一次改完。

**第 5 题。** 你和老师在网页上讨论了半小时，定下一个方案。然后你在终端里对 CC 说：「按刚才定的方案改。」会怎样？

- A　CC 照方案改。
- B　CC 不知道方案是什么，它没听到那场讨论。
- C　CC 会去网页上读聊天记录。

### 答案

**第 1 题选 B。** A 还是在琢磨「怎么说」，是第一层。C 是在控制「给它看什么」，是第二层。B 说一次就一直生效，是第三层。

**第 2 题选 C。** 502 是 Nginx 说的：我找不到后面的人转交。请求卡在第 4 步和第 5 步之间。

**第 3 题选 B。** Nginx 不管你登没登录，它只分流。第一个问「你登录了吗」的是守卫。被守卫拦下，后面的都不执行。

**第 4 题选 B。** 先加新的，老的不动。这样每一步做完系统都能跑。

**第 5 题选 B。** CC 是独立的环境。你没喂给它的，它就不知道。它还可能自己编一个「方案」出来照着改，这更糟。
