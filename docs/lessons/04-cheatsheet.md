# Lec 4 速查卡 · architect + 技术选型

能力：建重思考子代理(opus)并验真生效；6必问做约束分析；四象限选型；ADR-Lite 留决策。

三方法（已进 architect.md 附录）：
- 6必问：规模/团队/数据/部署/时间/演进。查不到的列「需主人确认」+假设默认值。
- 四象限：横轴契合度(吃约束) × 纵轴代价。右下甜区选，右上权衡(教学驱动归这)，左上排除。铁律：选型没绝对好坏，只有配不配约束。
- ADR-Lite：背景/决策/后果。后果必写「放弃了什么」。

四裁决：鉴权=DB session(非JWT，因登出即失效+角色即时生效)；Redis=MVP不引入留接口；实时=MVP通知表+轮询，WebSocket留Lec13；校验=Zod(两端共享schema)。

核心认知：约束驱动 vs 教学驱动。本项目复杂度是教学驱动的。看似矛盾的需求，先查来源，按时间线拆（本版兑现 vs 留某课兑现）。
