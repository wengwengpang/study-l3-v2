# Lec 1 完整笔记 · 用户研究

## 本课目标
用纪律版双 agent 做用户研究，推导项目方向，产出 USER_RESEARCH.md。

## 学到的能力
- 能建 subagent（带 YAML frontmatter 的独立角色文件）。
- 能让两个角色协作：client 问，persona 答，边界干净。
- 更正（问 719 甲，DECISIONS-R1 R1-668 第三点）：上面这条是原定要学的。两个角色当时只建好，没有实际运行。USER_RESEARCH.md 的六条出自 AI 写的张伟草稿，不是 persona 访谈产出。
- 能用假设账本区分「真人确认的需求」和「AI 假设的需求」。

## 核心设计 · 纪律版双 agent
- client：用户研究员，只提问和综合，绝不扮用户。tools 只给 Read。
- persona：假设目标用户，AI 设定，未经真人验证，产出全进账本标「待验证」。
- 为什么拆两个：一个角色又问又答会自问自答（反模式 5），拆开才挖得动。

## 诚实关卡（本课灵魂）
- 反模式 19：把 AI 编的需求当成已验证的真需求。
- Michael 诚实选了 C：对带团队的具体痛点无第一手信号，
  六条 persona 需求全标「待验证」，不以假 ✅ 充数。
- USER_RESEARCH.md 两栏物理分开：真需求栏诚实留空，假设栏六条待验证。
- 认知：项目「大方向」和「具体需求是否验证」是两回事。
  方向定了（团队任务协作），不代表具体痛点验证了。
