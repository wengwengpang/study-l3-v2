**3a · 原理**

**先接回段 1 那个门禁比方。**

你家里 CC 这个助手，面对每一道门。这套权限系统，就是给每道门贴一个牌子。牌子只有三种颜色。

**绿牌（allow）**：CC 自己刷卡就进，你不会被打扰。比如读文件、跑测试。

**黄牌（ask）**：门锁着，CC 得按铃喊你，你来了才开。比如推代码、动数据库。

**红牌（deny）**：门焊死了。CC 按多少次铃都没用，你自己都懒得来开——因为这种门压根不该开。比如删库跑路、偷看密钥。

三种牌子，就是配置文件里的三个清单：`allow`、`ask`、`deny`。规则写法是「工具名」或「工具名(具体条件)」，工具名首字母大写，比如 `Bash`、`Read`、`Edit`。

**接下来讲一个最容易搞错、但极其关键的规则：撞门顺序。**

CC 每次要动手，机器不是同时看三个清单，而是**排好队一个个看**：

先看红牌名单，再看黄牌名单，最后看绿牌名单。撞上第一个匹配的，就照它办，后面不看了。

这个顺序有个要命的后果：**红牌永远赢。**

举个例子。你在绿牌里大手一挥写「所有文件都能读」，但同时在红牌里写「`.env` 不能读」。CC 想读 `.env` 时，机器先翻红牌名单——撞上了，直接焊死，那条「所有文件都能读」的绿牌**根本轮不到看**。一条针对 .env 的红牌，能挡住再宽的绿牌。

这就是为什么这套系统安全：**你的绿牌可以给得很大方，因为你的红牌是真正的安全网，怎么都撬不开。**

**现在讲这一段最重要的一个认知——也是补强 3 落到实处的地方。**

你可能会问：那我把 D1-D7 全变成红黄牌，不就够了吗？

不行。因为机器的牌子，**只贴得住「能变成一条命令、一次文件操作」的东西。**

想想看：

D5「不可逆操作」——删库是 `rm`、是 `drop`、是 `git push`。这些是**具体命令**，能贴红牌黄牌。挡得住。

D2「动数据结构」——改 schema 是写 `prisma/` 目录下的文件。这是**具体文件操作**，能贴黄牌。挡得住。

但 D1「范围取舍」呢？「要不要把这个功能加进 MVP」——这是脑子里的一个**判断**，它不对应任何一条命令。机器没有正则能识别「CC 正打算做一个范围决策」。**贴不了牌。**

D3 权限口径、D6 需求来源、D7 藏取舍，全一样——它们是**语义**的，机器的墙拦不住。

所以两层是这样分工的：

**机械层（settings.json）**：兜住所有「能变成命令 / 文件操作」的高风险动作。这是硬地板，CC 漂移了也踩不穿。

**语义层（D1-D7 在 CLAUDE.md 里）**：兜住那些「只是个判断、没有对应命令」的决策。这层靠 CC 读宪法自觉停。

一个管手，一个管脑。手上那些危险动作用铁墙焊死；脑子里那些危险判断，靠宪法约束。两层互补，缺一不可。

**Level 1 对应**：你在网页版学 Claude Code 机制时，知道了「Permissions 分 allow/ask/deny 三档」这个概念。那时是**知道有这么回事**。这一步，是你第一次**真的为一个项目写出这个文件**，还把它跟你自己设计的 D1-D7 对齐。从「知道」到「配得出来」。

**3b · 操作：谁来做，为什么不给 CC**

这一步**你在终端直接建文件，不经过 CC**。

除了规则 31（宪法类文本老师出、学生落盘）之外，这里还有一个更硬的理由，你体会一下：

**不该让 CC 写它自己的权限文件。**

这是利益冲突。settings.json 是用来**约束 CC** 的那道墙。让被约束的人去砌约束自己的墙，这本身就不安全——它可能顺手给自己留个后门。还记得补强附带那条安全情报吗？配置文件是攻击面，谁能改它谁就能在你机器上跑东西。所以权限文件必须**由你亲手写**，CC 连碰都不碰。

因为全程不碰 CC，这一步**不涉及 Plan Mode**，你不用切任何模式。就是一条普通的建文件命令。

**3c · 拆段讲：这个文件三块，逐块看**

我把要写的 settings.json 拆成红、黄、绿三块，先讲清每块装什么、对应你哪把尺、罩住哪条 D，你看明白了，再给完整命令。

**第一块 · 红牌 deny（焊死的门）**

装什么：一执行就**不可逆、且没有任何正当理由该发生**的操作。对应你那把尺的极端角——可逆性为零、影响巨大。

放进去的：偷看密钥（`.env`、`secrets`）、递归删除（`rm -rf`）、提权（`sudo`）、任意联网抓取（`curl`、`wget`，这是数据外泄的口子）。

对应哪条 D：主要是 D5（不可逆）里那些「碰都不该碰」的。

**第二块 · 黄牌 ask（按铃喊你的门）**

装什么：高风险、**但有时确实合法**的操作。可逆性低或影响大，可你偶尔真需要它——所以不焊死，而是每次喊你拍板。这一块直接对应你 Level 1 的协议 12 双确认。

放进去的：推代码到远端（`git push`）、跑数据库迁移（`prisma migrate`）、改 schema 文件（写 `prisma/`）、改宪法本身（写 `CLAUDE.md`）、改 `.claude/` 里的角色和权限配置。

对应哪条 D：D5 里可逆性低的（迁移、推送）、D2（动数据结构）、还有「改宪法和权限文件」这种元操作。

**这里我特意克制——补强 4 说过，黄牌别塞满。** 只有上面这几样进黄牌，其余全下放绿牌。塞太多，你会被按铃烦死，护栏就形同虚设。

**第三块 · 绿牌 allow（CC 自己刷卡的门）**

装什么：可逆、低影响、你根本不想被打扰的日常动作。

放进去的：读文件、读 git 状态和日志、跑测试和 lint、列目录。这些错了也没关系、随手能撤，让 CC 自己做。

对应哪条 D：不对应任何 D——因为它们压根不是决策，是杂活。让它们隐形，你才有精力盯真正的黄牌。

**关键点（三个坑，都讲透）**

**坑一 · 空格加星号的边界。** `Bash(git log *)` 里，星号前那个**空格有意义**。`Bash(ls *)` 能匹配 `ls -la`，但匹配不到 `lsof`——因为空格划了词的边界，`ls` 后面必须真有个空格才算。这就是为什么我给 `git status` 写了**两条**：`Bash(git status)` 配没参数的，`Bash(git status *)` 配带参数的。不然裸跑 `git status` 可能漏网。

**坑二 · 红牌永远赢，别指望绿牌救场。** 上面绿牌写了 `Read(**)`（读任何文件），但红牌焊死了 `.env`。CC 想读 `.env` 时，红牌先撞上，直接拒。这是**故意设计的**——绿牌管大方，红牌管死守。

**坑三 · 通配符的确切行为，别信我，用机器验。** 这门课的信仰第二条就是「验证先于信任」。我照官方示例写了这些规则，但像 `Read(**)` 这种路径通配、还有空格边界，确切怎么匹配，**你该让机器自己告诉你**，而不是信我一张嘴。Claude Code 里有个 `/permissions` 命令，能列出当前生效的 allow / deny 规则。下面审查清单里我让你跑它。

补一句 `$schema` 那行的作用：它指向官方的 JSON schema，让 VS Code 这类编辑器能自动补全和校验这个文件。纯为了你写着顺手，不影响运行。
