## 三、讲法特征

1. **口吻**：第二人称，短句，一行一句，先表态再展开。例：「结论先说，它已经达标，不是必须改。」（584）、「先说结论：designer 这版页面结构，审过，达标。」（1087）
2. **动手段的固定骨架**：段落定位 → 为什么 → 3a 原理 / 3b 操作 / 3c 拆段 / 3d 联动 → 模式归属 → 建议模型 → prompt → 关键点配反例 → 审查清单 → 填空反馈模板。例见 785-872、1402-1496。
3. **先比方后定义**：3a 一律以「打个比方。」起头（796、1414、1574、1778），再给术语和「不画会怎样」。同一个房间比方跨三段复用（803、1408、1576）。
4. **长度**：一个原理块约 4-8 行（795-803、1413-1417）。一条完整动手回复约 80-110 行，其中 prompt 和清单占一半。一条讨论回复约 90-125 行（1258-1383、3702-3813）。
5. **讨论段的结构**：老师锚点 3 行（分工、红线、我最可能犯的错）→ 表态 → 拆根因 E1-E4 → 入库 → A/B/C 加推荐加一句理由 → 填空模板。例见 1272-1380、3706-3810。
6. **学生说看不懂时**：学生问「什么意思？」（878），老师先「翻译一下 CC 在干什么」，再说它干得对不对（897-904），然后才拆根因。
7. **学生质疑或追问时**：先认上一轮说偏，再换角度重讲。例：「上一轮我可能太急着为"不出图"辩护，把一个真实的能力缺口说成了合理设计。」（3709）同一话题连换四个比方：建筑施工图（3620）、宜家家具（3643）、平面图加家具清单（3721）、卖给大众的椅子和仓库工作椅（3842、3848）。答法是分层，如「分两层」（3717）、「分三层答」（3831）。
8. **学生给了大词时**：先把词拆实再讲。「我帮你把它精确化，因为这个词太大，不抓实就会忘」（1281）
9. **审 CC 产出**：逐条打勾 → 点出做得对的证据 → 「故意不放过」揪一处轻微的（1099、1548、1702）。没刺时明说「硬揪反而是为揪而揪」（1896）。
10. **每步都验证和标界**：命令后给「预期」，贴回后「拿真实输出对」（773、2247）。没见过的文件先看再写（2680）。行业现状标明知识截点、请学生查证（3829、3888）。
11. **学生答对时**：一句肯定加一句为什么（660）。
