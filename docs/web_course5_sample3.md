## 四、核心问题：保安、通行证、档案室

第 2 点是整份报告的中心，我用一个比方讲透它。

你这栋楼的规矩是这样的：

大门口有个保安。他负责查一件事——**你是不是这栋楼里某家公司的员工**。他手上有一本花名册（project_memberships），翻一下就知道。

规矩还写着一条：**保安不许进档案室。**（这就是「Guard 不查业务表」。）

现在来了一个访客，他要去看一份文件。他手里只有一张通行证，上面写着「文件编号 A-217」。

保安傻眼了。他要查「你是不是某家公司的员工」，可他得先知道**是哪家公司**。而「A-217 属于哪家公司」这个信息，写在档案室里。

## 五、T2 · 项目 id 从哪来（本节最重要的一票）

**选项 A：改通行证。任务类接口一律嵌套项目 id。**

网址长这样：`/projects/{项目id}/tasks/{任务id}`。保安直接从通行证上读到公司名，不用进档案室。

好处：`Guard 不查业务表` 这条界线保住了。决策 3「权限口径集中」也保住了。而且这是 REST 的常规写法，Jira、Trello 的 API 都这么排。

代价，architect 点得很准，我展开讲，因为它不明显：

**Service 必须额外核对「这条任务确实属于这个项目」。**

为什么。假设我是项目甲的成员。我把项目乙的某个任务 id 填进甲的路径里：`/projects/甲/tasks/乙的任务`。

保安查花名册：这人是甲的成员，放行。
Service 拿任务 id 去查 tasks 表，取出来就返回。

**我就读到了项目乙的数据。** 我压根不是乙的人。

这叫越权读取。所以选 A 的话，第三节里必须明确写一步：Service 取到任务后，先比对 `task.projectId` 和路径里的项目 id，不等就拒绝。

换句话说，**A 不是免费的。** 它把一次检查从 Guard 挪走了，但挪来的是另一次检查，而且这次检查必须写进文档，不能靠人记得。

**选项 B：让保安进档案室。Guard 自己查 tasks 拿项目 id。**

好处：网址短，前端简单，不用改路由。

代价：`Guard 不查业务表` 这条界线彻底作废，第二节要大改。而且同一条 task 会被查两遍——Guard 查一遍拿 projectId，Service 再查一遍拿内容。要避免查两遍，就得新定义一个「Guard 把结果传给 Service」的机制。NestJS 里技术上能做（挂到 request 对象上），但那是新机制，得显式写进架构，不能默认它存在。

**选项 C：把这道检查挪到里面。只带任务 id 的接口，成员校验下放到 Service。**

好处：不改路由，不改 Guard。

代价：角色级判定分散到两层。而你当初拍决策 3（authz 独立成模块）给的理由就是「口径必须集中，加角色改权限只动一处」。选 C 直接削弱这条理由。

**我推荐 A。**

一句理由：它是唯一能同时保住「Guard 不查业务表」和「权限口径集中」两条已定原则的选项，付出的代价是一次写得进文档、说得清楚的归属核对，而不是一条变模糊的界线。

## 六、T3 · 网址里的 id 在哪校验

这条和 T2 绑在一起，所以放一起拍。

先说清楚问题。层序是 Guard 在 Pipe 之前。也就是说，**保安看到通行证的时候，通行证还没被验过真伪。** 如果 T2 选 A，Guard 要用路径里的项目 id，而那个值是原始字符串，没经过任何校验。

**我推荐 A。** 一句理由：不新增层、不给 Guard 加职责，而且和本项目已经拍过的「无权限与不存在合并」口径天然一致。

### T1 · 服务端用什么跑 Zod

**问题在哪。** NestJS 自带一个 ValidationPipe，但它认的是 class-validator 那一套——要你写带装饰器的 DTO 类。而你选的是 Zod，还拍过「不手写 DTO，用 z.infer 推导」。

### T4 · 会话要不要续期

**问题在哪。** PRD.md:160 写「30 天有效期内保持登录」。这句话有歧义。

是**从登录那刻起算 30 天，到点就下线**？还是**每次用都往后推 30 天，只要在用就不下线**？

**Level 1 对应**：TaskFlow 那次你用的是 JWT。JWT 是无状态的——令牌发出去就管不着了，想让它提前失效得另建黑名单。本项目改成 DB session，就是因为约束变了（要求登出立即失效、角色改后即时生效）。**而正因为 session 存在库里，「续期」才成为一个需要你拍板的选项**——JWT 时代这个选项根本不存在，你只能重发令牌。选型一变，要拍的板也跟着变了。

### T5 · 分配任务时，assignee 要校验到什么程度
