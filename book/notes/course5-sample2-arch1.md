## 二、知识点清单

分类简写：【工程】指系统架构或软件工程本身的知识；【协作】指怎么和 AI 协作干活；【课务】指这门课怎么上的安排；【拿不准】照写，并说明为什么拿不准。

### （一）开课第一轮（1-380 行）

1. **补课定位：有意拆分，不是漏掉**（62-70）【课务】
   Lec 5 只做了 schema。architect 还有四件产物（系统架构、API 契约、共享类型、环境设计）当时拆出去延后了，「这是有意拆的，不是漏掉的」（66）。补课分四小节：05-ARCH → 05-API → 05-类型 → 05-环境（70）。

2. **逻辑顺序和实际执行顺序**（72-88）【课务】
   逻辑顺序是 Lec 05 → 05-ARCH →…→ Lec 06 → Lec 07（77），实际是 Lec 05 → Lec 06 → 补课 → Lec 07（80）。两者分不清，就会重蹈反模式 34（74）。盖房子比方：家规（CLAUDE.md）已经贴上墙了，现在回头补户型平面图（84-86）。老师说：「我知道你已经掌握 D1-D7…这些我不会重讲」（88）。

3. **课程地图**（90-95）【课务】
   现在是 Phase 0，不写业务代码。补完课之后重开 Lec 07，那节有 SG-1 第一个过关点（95）。

4. **分工和两条要点**（99-109）【协作】
   「审 CC 输出的人是你，不是我审你。我给你审查清单，你对着清单一条条核」（107）。「architect 是 Read-only 角色……ARCHITECTURE.md 是它给内容、你 `cat` 落盘」，这是 AGENT_SPEC 权限表定死的（109）。

5. **没读过的文件，不说里面写了什么**（113-117，205-213）【协作】
   「任何关于它们内容的话，我现在都不能说。说了就是编（反模式 1 号）」（117）。规则 57 第 9-11 项等还没读到，「现在报'通过'就是假的，那正好撞上反模式 3 号」（211）。

6. **开课先核 git，分三种情况处理**（119-146）【协作；命令本身属工程】
   预期最近一条提交是 2ce5304（131）。只有 anti-patterns.md 一个改动，才直接 add 和 commit（135-140）。还有别的改动，就「先别 add，先贴给我看」（142）。另外交代「不要回滚任何东西」（146）。

7. **读中文不要用 cat -A**（150-152）【工程】
   cat -A 会把中文显示成 `M-xM-yM-z` 这样的乱码，这是反模式 22（152）。

8. **七个文件分两批贴，路径必须是真的**（165-173）【协作】
   第一批是自检要用的，第二批是写 prompt 要用的（167-169）。architect 定义文件的路径「我必须拿到真的」：路径写错它就读不到，人设也就不生效。这是反模式 7 叠加反模式 3（173）。

9. **漂移自检 K 节 8 项**（179-203）【课务】
   逐项报「通过」。样板 A 用在要学生动手的步骤，样板 B 用在被质疑或讨论的时候（185）。填空模板「只用来接你的回话，不能拿来代替我的讲解」（197，TEACHING_STYLE 第八节）。新规则从 67 起编号，新反模式从 35 起（203）。

10. **复述规则 61：七文件维护**（215-227）【课务】
    三句话：开课读全、结课逐查、harness 产物往上沉淀（217-225）。老师同时声明：「规则 61 的原文我还没读到……有出入，以原文为准」（227）。

11. **05-ARCH 的目标和可追溯要求**（233-241）【工程；「当场打回」属协作】
    架构文档要写清模块划分、前后端分层、数据流、部署拓扑（235）。「每一个架构决策，都能往回追到 PRD、schema 或者技术栈的某一行。追不到的，就是 architect 自己编的，当场打回」（241）。

12. **为什么先做架构，再做 API 契约**（243-253）【工程】
    schema 是仓库里的货架（247），ARCHITECTURE 是厂区平面图（249），API_CONTRACT 是车间之间的交接单（251）。「平面图没画，你不知道有几个车间，就不知道要开几种交接单」（253）。

13. **五段大纲和课数弹性**（255-275）【课务】

## 三、讲法特征

1. **每条回复都以「老师锚点（3 行）」开头**：分工、红线、「这一步我最可能犯的错」。出现位置：54-58、386-390、868-872、1293-1297、1569-1573、2180-2184、2602-2606、3028-3032、3526-3530、3937-3941、4244-4248、4511-4515、4982-4986。第三行每次都写一个具体的预判，例如「架构师这份输出写得很漂亮……我顺着它讲一遍就完事」（872）、「只对着你填的模板核，不看你贴的原始输出。今天差点就漏了」（2606）、「你说'简单回答'，我讲成一整段课」（4248）。

2. **比方先行**。常用写法是「打个比方。」单独一行，再展开，一个比方撑完一段。例子：盖房子（82-86）、货架/平面图/交接单（245-253）、家规和金库锁（510-518）、公司部门「这个比方我撑完整段」（613-623）、部门互相等（958-960）、人事部和门禁室（1045-1049）、顾问回家（1339-1341）、顾问只有阅览室钥匙（1609-1611）、钉子和挂钩（1705-1709）、挂钩没人挂（1749-1755）、锁不在保安清单上（2234-2240）、门口换保安（2654-2658）、大门的锁（2686-2690）、餐厅「这个比方撑完整段」（2767-2777）、水管通二楼（3068-3070）、门锁说明书（3133-3139）、保安和前台（3187-3193）、后厨和前台（4306-4312）。

3. **讲解段有固定骨架**：段落定位 → 这段为什么这么做 → 3a 原理 → 不做会怎样 → 3b 操作 → 3c 拆段讲 → 3d 联动 → Level 1 对应 → 对应 KB → 模式归属 → 建议模型 → CC 的 prompt → prompt 关键点（配反例）→ 审查清单 → 反馈模板。第 1 段在 592-835，第 2 段在 2746-3002，两段完全同构。

4. **让学生拍板的方式**：每个决定都给 A/B/C 选项，写「我推荐 X」，再列编号理由和「诚实说代价」；常加一句「不阻塞」或「可以结课再定」（326-332、488-500、1051-1066、1236-1248、1440-1454、2705-2721、3410-3418）。信息不够时明说不给推荐（1169-1177、1651）。原话有「我不替你拍板」（488）、「这类决定归你，不归它（强化 16）」（793）、「这不是我替你定，你可以选」（3412）。

5. **决策全课连续编号，每轮末尾给填空模板**。决策从 1 编到 18，学生回填模板就算拍板（1258-1269、1472-1489、2015-2030、2450-2466、2980-3001、3362-3385、3873-3885、4175-4195）。老师强调模板只用来接回话，不代替讲解（197）。
