# 第 2 课完整笔记 · 激活 pm,产出 PRD

## 本课位置
Phase 0 立项第 3 步。上承 Lec 1 用户研究,下启 Lec 3 UI 设计。

## 学到什么(大白话)
1. 建了 pm 角色(边界守护者),照 AGENT_SPEC 建,只给 Read 权限。
2. 懂了三块积木:PRD 是施工图,用户故事是积木(作为谁/想做什么/以便什么),验收标准要可测(给定…当…则…)。
3. 第一次让角色真干活:pm 把六条需求转成用户故事,条条标「假设」。
4. 第一次以"项目主人"身份下场,逐条确认,把假设升级成「已验证」——假设账本真正运转。
5. 证据契约的两种形态:代码引用要 文件路径:行号;需求要标来源(真人/AI 假设)。

## 关键决策
- 九条故事全部经 Michael 确认,标「已验证」。US-02 拆成 US-02a(可见)/US-02b(预警)。补 A/B 升级为 US-07/US-08。
- 认了 US-07(执行者视角)→ 产品从单视角变双视角,影响 Lec 5 数据建模、Lec 11 前端、Lec 13 权限。
- CLAUDE.md 第二层用精简骨架(A 法),详情指回 PRD.md。
- 提出 harness 终极目标 → 定为课程方针(规则 59),进 COURSE_RULES 不进桥梁。

## 制度升级(本课重头)
- 规则 59:harness 目标为课程方针,可复用产物往全局/模板沉淀,项目私货留项目。
- 规则 60:六文件结课维护 + 开课结课双闸自检,并写清与 K 节/规则 57 的叠加关系。
- 规则 61:传承链元检查,确认新产物有持久文件接住、能自动传到下一课。
- 反模式 24:重要意图错放桥梁。25:制度不能自传承。26:新增制度没说清与旧制度衔接。
- 3 号反模式升级为"表象成功≠实质生效",涵盖角色和文件两种验证。

- 老师自己在写规则 60 时犯了反模式 25(没说清与旧自检衔接),被 Michael 当场抓出 → 印证了新规则有用。
